# 组装管线（Markdown → 合并版 → 出版级 docx）

> 本文件供 long-form-book-writing 技能阶段 5 使用。核心原则：**单脚本、对源文件只读、全流程幂等**——重跑 `python3 assemble_book.py` 即全量再生成，源稿永不被构建过程改动。

## 1. 脚本五步架构

```
分章 markdown（源稿，只读）
   │
   ├─ 第一步：组装 markdown
   │    BOOK_ORDER 顺序表 →（篇扉页插入）→ 特殊规则（脚手架剥离）
   │    → 草稿注释清理 → 弯引号规范化 → 表块空行规范化 → 图片路径重写
   │    产出：输出/全书稿_合并版.md
   ├─ 第二步：图片压缩（审阅用副本，源图不动）
   │    2048px PNG → 1600px JPEG（quality≈85），仅嵌入 docx 用
   ├─ 第三步：生成 reference.docx 样式模板
   │    中文字体方案：正文宋体/标题黑体/引用楷体（East Asian＋ASCII 字体都要设）
   │    自建 TOC 1–9 样式（pandoc 默认模板没有）
   ├─ 第四步：pandoc 转换（pypandoc）
   │    markdown → docx，挂 reference.docx；中文书关闭 smart 扩展（-smart）
   └─ 第五步：docx 后处理（python-docx / lxml）
        静态目录替换域目录 → 表格边框/版心等宽/跨页重复表头
        → 图居中 → 页脚页码 → A4 版心与边距
   产出：输出/全书稿_合并版.docx
```

依赖：`pypandoc-binary`（自带 pandoc 二进制，免系统安装）、`python-docx`、`pillow`。

## 2. 组装层规范化（第一步细节）

| 处理 | 做法 | 为什么 |
|---|---|---|
| 顺序表 | `BOOK_ORDER = [('part', 篇名, 扉页图), ('file', 章文件名), ...]` | 成书顺序与文件名解耦，插篇扉页不改源稿 |
| 脚手架剥离 | 特殊规则表：{文件名: 从哪一行起保留} | 写作期元标题/状态块是脚手架，成书不要 |
| 草稿注释清理 | 识别标记（引用块＋固定关键词，如"书稿状态""排版说明""标注位"），默认删，`--keep-notes` 保留 | 送审版干净，工作版可回溯 |
| 弯引号规范化 | 逐行扫描，ASCII 直引号按行内配对转为中文弯引号（" " ' '） | 多来源文本引号混杂；pandoc smart 在中文语境反而添乱（见 §3 坑 1） |
| 表块空行 | 管道表前后强制补空行（`ensure_table_blank_lines`） | 坑 2 的根治 |
| 图片路径重写 | 分章相对路径 → 合并版统一路径 | 合并后目录层级变化 |

## 3. pandoc / docx 已知坑与解法（实测清单）

1. **smart 扩展毁中文引号**：pandoc `smart` 把 ASCII 直引号在中文语境误转为两个同向弯引号 → 转换时**关闭 smart**（`-smart`），引号问题在组装层自己按行配对处理；
2. **管道表被当普通段落**：表体与上一行（如表题行）**紧贴无空行**时，pandoc 不识别为表格，输出原样管道符 → 双保险：脚本对表块前后自动补空行＋源稿同步修复；验收指标：docx 中正文段落无残留 `|`，表格总数符合预期（实测修复后 86→90）；
3. **`--toc` 生成的是 Word 域目录**：不手动"更新域"就是空白页 → 后处理删域目录，**自建静态目录**（TOC Heading＋TOC 1/2 段落，直接写条目文本）；同时 reference.docx 必须**自建 TOC 1–9 样式**（pandoc 默认模板缺失，否则目录无样式）；
4. **大图撑爆 docx**：69 张 2048px PNG ≈168MB，直接嵌入不可用 → 构建前压缩为 1600px JPEG 审阅副本（成品 8.3MB）；**源图不动**，`--no-resize` 可关；
5. **中文字体要设两套**：docx 样式的 East Asian 字体与 ASCII 字体分别设置（rPr 的 w:eastAsia＋w:ascii），只设一个会出现中英混排字体错乱；
6. **表格版心等宽**：按版心宽度（A4 21cm − 左右边距）统一设置表格宽度与单元格边距，否则每张表宽度随内容漂移；跨页表**标记重复表头行**（tblHeader）；
7. **页脚页码**：python-docx 不直接支持域，需手写 `PAGE` 域 XML 注入页脚；
8. **环境缺小工具**：`bc`/`unzip`/系统 pandoc 常缺席 → 一律用 python 单行或 pip 包替代，脚本自包含。

## 4. Flags 设计（工作版/送审版两用）

```
--keep-notes     保留草稿注释（工作版）
--no-cn-quotes   关闭弯引号规范化（源稿已规范时）
--no-toc         不生成静态目录
--toc-depth N    目录深度（默认 2：章＋节）
--no-resize      不压缩图片（打高清审阅版）
--outdir PATH    输出目录
```

## 5. 幂等与验证纪律

- 脚本对源文件**只读**：任何"顺手改一下源稿"的冲动都改为在规范化层做，或回到源稿人工改后重跑；
- 每次重跑后做**构建体检**（见 audit-and-handoff.md §3）：H1 数＝预期章节数、目录条目数、内嵌图数、表格数、残留管道符段落数＝0；
- 合并版 md 同时是**审计的工作对象**：断链/编号/引号检查全部跑在合并版上，一次覆盖全书。
