# 策划案与进度文件模板

> 本文件供 long-form-book-writing 技能阶段 1–2 使用。模板从一部 17 万字符、15 章＋6 附录、69 张插画、39 张表的成书项目中提炼，可按体量裁剪。

## 1. 策划案六部分骨架

文件名建议：`《书名》图书策划案与详细大纲.md`。六部分缺一不可：

### 第一部分　图书基本信息
- **书名方案**：主书名 2–4 个候选＋副书名；每个候选一句话说明取向（亲和/专业/悬念）；
- **一句话定位（电梯陈述）**：给谁、解决什么、与同类书差在哪；这句话之后直接复用为封底文案的种子；
- **基本信息**：预估字数、章节数、开本形态、配套资源（实验/表单/模板件）；
- **目标读者**：唯一预设＋三条"读者画像"具体行为描述（他们会做什么、卡在哪）；
- **卖点与差异化**：逐条对照市面同类书。

### 第二部分　核心写作理念
- **全书总纲**：把源材料的核心论断转化为全书立意（一段话）；
- **核心比喻体系**：一个总比喻统摄全书（如"AI 是数字见习生"），部件各有子比喻；
- **比喻对照表**：技术概念→生活比喻逐条登记（两列表格，30–80 行），正文写作时照表执行，禁止临场发明新比喻；
- **写作原则（含语气红线）**：6–10 条，其中至少一条是"禁止项"（不制造焦虑/不俯视/不身份化吹捧）；红线违反一票否决；
- **导流机制**（见 §4）；
- **源材料→章节映射表**：有参考资料时必做；左列源材料概念、右列覆盖章节；审计时反向核对"每个概念至少出现一次"。

### 第三部分　体例模板（两套以上章模板＋统一栏目）
为不同性质的章各定一套骨架（示例见 §2）。统一栏目符号全书一致，例如：

```
◆ 术语卡　　◆ 概念桥　　◆ 比喻的边界　　◆ 动手试试
◆ 原理速览　◆ 边界提醒　　◆ 时效提示　　◆ 深化路标
```

栏目符号用特殊字符（◆）开头，保证 grep 可数、审计可查。

### 第四部分　详细目录与逐章大纲
- 全书结构总览（篇→章一张表）；
- 每章一节：一句话目标、小节清单（到二级标题粒度）、图表规划（哪几张图/哪几张表/编号预留）、目标字数；
- 大纲粒度标准：**照着大纲能直接开写，不需要再做结构决策**。

### 第五部分　前言、后记与附录方案
- 前言：写什么、不写什么（致谢与真实案例留占位）；
- 后记：立场声明（如 AI 参与范围披露）用【方括号占位】；
- 附录逐个规划：术语表（条数与分组）、检索速查（现象索引总表）、场景配方集、延伸阅读、教学使用建议、实验指南与记录表等——附录是"手册式导流"的落点，规划时与导流机制对齐。

### 第六部分　字数分配与写作计划
- 字数分配表：每章目标字数＋合计（预留 5–10% 弹性）；
- 排期（供参考）；
- **质量风险控制**：预列风险与对策（比喻失真→边界框兜底；章节失衡→达标率区间；前后矛盾→金句锚点＋术语表对齐）。

### 附：文风示范段
约 200 字成品风格样段。全书开写前用它校准语气；写作中途风格漂移时回来对表。

## 2. 章模板骨架示例（两套）

**动手章模板**（入门/实战篇）：

```
# 第 x 章　章名
本章目标（3 条以内，可验证）
§x.1 最少必要概念（只讲本章动手所需的，其余交给导流）
§x.2 分步动手（步骤化，每步有"你会看到什么"）
§x.3 实验 x（编号全书连续）＋记录表单（T-xx 在位嵌入）
◆ 比喻的边界（本章所用比喻在哪里失真）
本章小结＋思维导图（图 x-n）
实践任务（选做）＋下一章导流（一句话钩子）
```

**理论章模板**（深入篇/手册式）：

```
# 第 x 章　章名
现象入口（读者会遇到的具体现象/故障，2–3 个）
◆ 原理速览（半页讲清机制，可独立阅读）
展开论述（机制→案例→边界）
◆ 深化路标（指向附录/其他章的检索指针）
◆ 边界提醒／时效提示
本章小结＋思维导图
```

模板是**底线不是天花板**：允许按章加节，但骨架项（目标/小结/导图/导流/边界框）不可缺。

## 3. 贯穿元素设计

动笔前定死，写进进度文件"写作约定"节：

- **贯穿人物**：一个名字、一句身份（身份不指明专业/行业，扩大代入面）、一条成长叙事线（第 1 章登场→中期挫折→末章回声）；
- **贯穿案例**：一条真实感任务线串起所有章节的动手环节；
- **双轨实验**（若书含动手环节）：A 线主工具、B 线替代工具；B 线缺能力时给"人肉替代法"，保证不同条件的读者都能完成；
- **实验统一编号**：实验 1–n 全书连续，附录汇总速查表＋总台账表单。

## 4. 导流机制（手册式结构的核心）

目标：正文薄、可顺序读；附录厚、可按需检索。四件套：

1. **现象索引**（附录）：读者症状→章节/小节的两级总表（"遇到什么→去哪看"），40 条以上；
2. **原理速览**（章内栏目）：每章半页可独立阅读的机制概述，忙碌读者只读这些也能成体系；
3. **深化路标**（章内栏目）：正文→附录/其他章的显式指针，格式统一（"想看 X，去 §y.z / 附录 B 第 n 条"）；
4. **速查卡**（附录）：高频操作的单页速查＋可复印模板件。

审计阶段逐条核对导流双向可达：路标指的目标存在、索引条目与正文小节号一致。

## 5. 进度文件模板（`00_书稿进度.md`）

```markdown
# 《书名》书稿进度表（vX.Y）

> 依据：《书名》图书策划案与详细大纲（vN）
> 体例：动手章按策划案 §3.1 模板，理论章按 §3.2 模板；全书零代码；语气红线见策划案 §2.4
> 本表为全书唯一进度权威；最后更新：（一句话说明本批次做了什么）

## 一、总体状态
（3–6 条 bullet：正文完成度、图表在位数、配套交付物、零断链声明）

## 二、文件清单与达标率
| 文件 | 目标字数 | 现字数 | 达标 | 状态与备注 |
（每章一行；备注写"补差几轮、补了什么"，让达标率可追溯）

## 三、版本历史
| 版本 | 内容 |
（每批次一行：v0.1 初稿 / v0.2 扩写 / v0.3 插图插表 / … / v0.8f 终态）

## 四、全书写作约定（执行中/执行完毕）
（贯穿人物与叙事线；双轨工作台；图表引用格式；栏目符号清单；
　模板件排版方式；金句锚点 N 句全文照录；编号规则）

## 五、剩余工作（全部为外部依赖或人工环节）
| 事项 | 依赖 | 说明 |
（占位事实填充→作者；四轮审校→工程师/读者/编辑；设计师工序→插画师/排版；
　出版配套→编辑。AI 可做的事做完即从本表消失）

## 六、可选的后续动作（书稿侧）
（封底文案、按审校反馈修订 v0.9 等；已完成的划掉并注日期）
```

**维护纪律**：
- 每个工作会话收尾前更新"总体状态＋达标率行＋版本历史"三处；
- 金句锚点在 §四全文照录（不只列名），审校时逐句 grep 核对措辞一致；
- 版本历史每行须能让第三方看懂"这批改了什么、为什么"——它是项目的黑匣子；
- 剩余工作表只留外部依赖；终态版进度文件 = AI 侧零未销项的声明。

## 6. 达标率与补差操作法

- 区间建议 90–120%：<90% 必补，>120% 评估是否削（余量留给出版编辑润色属正常，不是缺陷）；
- **补差四轮法**（实测有效）：每轮通读挑 4–7 个"信息量缺口"（缺病例、缺反例、缺边界、缺数据感），逐个补小节；轮次间隔一轮做别的章，避免原地打转；
- 补差来源优先级：真实病例/失败案例 ＞ 边界情况 ＞ 追加对比小节 ＞ 加深比喻阐释；**禁止**：排比堆砌、同义反复、注水对话；
- 每轮补差在进度文件备注列写清"补了什么"（如"＋账单段/成熟度直觉/反向测量"），使字数增长可审计。
