# 长篇图书写作（Long-form Book Writing）

把"写一本书"当成一个**工程系统**来运营：结构先于写作、权威文件先于内容、资产登记先于生成、审计先于交付。

## 何时使用

- 用户要写一本书、长篇教程、系列讲义、培训教材（目标 ≥5 万字符）；
- 用户有一批技术笔记/文章/讲稿，要整理成结构化书稿；
- 用户要对既有长篇书稿做体例统一、审计、合并导出（可直接跳到阶段 5–7）。

单篇文章、短报告（<1 万字符）不必启用全流程，但 `references/audit-and-handoff.md` 中的审计清单仍然适用。

## 核心理念（先读这一节，再动手）

1. **书是系统，不是文章的堆叠。** 教学结构（阅读顺序、导流机制、比喻体系、贯穿人物/案例）必须在动笔前设计完毕，否则写到后半程撑不住前半程。
2. **三份权威文件，各管一段，落盘维护：**
   - **策划案**＝书的宪法：写什么、怎么排、每章多少字、语气红线；
   - **进度文件**（如 `00_progress.md`）＝唯一进度与约定权威：达标率表、版本历史、金句锚点、剩余工作；
   - **资产母本**（表格成品集、插画交付清单）＝图表内容与生成 prompt 的唯一权威。
   每个工作会话结束前，进度文件必须已更新。
3. **一处写，处处同步。** 同一内容存在"母本＋章内阅读版"两份时，把同步纪律写进进度文件，此后每次改动双向照改，审计时逐条核对。
4. **占位事实宁缺毋假。** AI 不可能知道的事（致谢对象、署名日期、产品版本号、时效日期、真实案例细节）一律用【方括号占位】写入，并登记进"剩余工作表"，绝不编造。
5. **源稿神圣，构建层承担一切加工。** 草稿注释剥离、引号规范化、图片压缩、排版转换全部进组装脚本；脚本对源文件只读，重跑一次即全量再生成（幂等）。
6. **落笔即合规（排版第一次就做对）。** 写书稿时第一次就按《中文排版指北》来撰写 markdown，禁止先随意写、事后批量修复。每段写完立即跑排版自检脚本，退出码 0 才算干净。理由：事后修复会污染文件名扩展名、shell 记号等白名单写法，返工浪费远大于当场注意。
7. **凡资产必登记、凡交付必审计。** 每张图、每张表、每句金句都有编号和登记处；交付前跑四类自动终检（断链/编号/引号/表格）。
8. **风格一致性（插画和图表的最高铁律）。** 所有插画和图表必须使用一致的风格（线条粗细、配色方案、字体字号、圆角大小、阴影风格等），禁止同一本书中出现多种视觉风格。做法：全局风格前缀逐字粘贴、统一资产库、风格样张定调、每批生产完后并排目检。理由：风格不一致会让读者困惑"这是同一本书吗"，严重影响专业性和阅读体验。

| 2 | 进度骨干 | `00_progress.md` | references/planning-and-progress.md |

### 阶段 0：定位对话（先问，再写）

用提问工具（或列出问题清单）与用户确认以下五项，结论全部写进策划案：

1. **读者唯一预设**：读者会什么、不会什么？只预设一条（如"完全没有编程经验"），不叠加身份标签；
2. **语气红线**：明确禁止项。常见三条：不制造焦虑、不俯视说教、不做身份化吹捧或安抚；
3. **阅读契约**：对读者的可验证承诺（如"全书零代码""30 分钟完成第一次动手""每个比喻都交代边界"）；
4. **教学结构**：目录顺序 ≠ 学习顺序。常见形态：线性递进；**倒装结构**（先入门→再动手→然后深入→最后边界）；**手册式**（正文薄、附录厚、按现象检索导流）。选定后设计导流机制（详见 references/planning-and-progress.md §4）；
5. **源材料映射**：若有参考资料，逐概念建"源材料→章节"映射表，确保无遗漏、可验收。

### 阶段 1：策划案

按 references/planning-and-progress.md 的六部分模板产出。要点：

- 章模板准备**两套以上**（如动手章/理论章各有固定骨架），不用一套万能模板；
- **栏目符号全书统一**（◆ 术语卡｜比喻的边界｜动手试试……），可 grep、可审计；
- **比喻对照表**先于正文：技术概念→生活比喻逐条登记；每个比喻在使用处必须紧跟"比喻的边界"框，说明它在哪里失真；
- **金句锚点**：预定 8–12 句全书核心句，措辞登记在策划案与进度文件，审校时逐句核对一致；
- 每章大纲含：一句话目标、小节清单、图表规划、目标字数；
- 附 200 字**文风示范段**，供全书体例校准。

### 阶段 2：进度文件

创建 `00_progress.md` 并维护到项目终态，六节结构（模板见 references/planning-and-progress.md §5）：总体状态、文件清单与达标率、版本历史、全书写作约定、剩余工作（标注依赖方）、可选后续动作。

- 每章设**目标字数与达标率区间**（如 90–120%）：低于下限补差、高于上限考虑削；
- 版本号纪律：v0.1 初稿 → v0.2–x 扩写补差 → v0.x 插图插表 → v0.8 书稿终态 → v0.9 审校修订 → v1.0 定稿；每批次改动记一行版本历史；
- "剩余工作表"只放**外部依赖或人工环节**，AI 可完成的事项做完即销项。

### 阶段 3：逐章写作

1. 按模板骨架逐章写，**每章完成立即回填进度文件对应行**（字数、达标率、备注）；
2. 写作中对照策划案大纲防漂移；需要改结构时，**先改策划案，再改正文**，两处同批次完成；
3. **补差用信息量，不用字数**：章节不足时补病例、反例、边界情况、追加小节，不堆排比、不车轱辘话；
4. 草稿期注释（书稿状态块、排版说明、标注位说明）用统一可识别标记（如引用块＋固定关键词），供组装脚本一键剥离（`--keep-notes` 可保留）；
5. **贯穿元素**（人物、案例、实验编号）全书一条线：每章开头承接、结尾导流下一章；实验/任务统一编号并在附录汇总；
6. 占位事实随写随标【方括号】，随标随登记进进度文件"剩余工作表"。
7. **排版自检（铁律）**：每段写完立即跑排版自检脚本（如 `python3 workstation/typography-check.py manuscript/chNN.md`），退出码 0＝干净。有问题当场改，禁止攒批返工。依据《中文排版指北》，重点检查：①中英文之间加空格；②中文与数字之间加空格；③全角标点前后不加空格；④Markdown 强调标记紧贴中文标点时须闭合无歧义；⑤专有名词按官方大小写。

### 阶段 4：资产体系

表格与插画是与正文并列的**第三个工作面**，需要母本、编号、prompt 登记与验收清单。完整规范见 references/asset-systems.md，核心要点：

**★ 图表铁律（强制）**：
- **中文必须正常显示**：markdown 转 docx 时，所有图表中的中文禁止出现不显示或方框（tofu）。做法：docx 嵌入前预栅格化为 300DPI PNG，字体链包含 CJK 回退链（Noto Sans CJK SC 优先），交付前逐图检查 `.notdef` 字形。
- **宽高比必须匀称**：单栏图宽高比 4:3～16:9（0.75–1.8），通栏横幅图 ≤2.5:1，跨页竖图 ≥1:2。不得出现细带或竖条出厂。使用 `mmd_square.py` 自动校验和调整。
- **风格必须一致**：所有插画和图表必须使用一致的风格（线条粗细、配色方案、字体字号、圆角大小、阴影风格等）。做法：①全局风格前缀逐字粘贴；②统一资产库，角色与比喻物形象全书一致；③风格样张定调，作为后续所有图表的对照基准；④每批生产完后并排目检，确认风格一致。禁止同一本书中出现多种视觉风格。

**插画体系核心**（详见 references/asset-systems.md §2）：
- **先定调，再量产**：风格样张 → 全局风格前缀 → 负面提示 → 角色资产库（§2.1.1）
- **画面无文字铁律**：AI 出无字底稿 → 设计师矢量加字（两段式工作流 §2.6）
- **封面多方案**：出 2-3 个方案，登记候选状态与推荐理由（§2.7）
- **交付批次**：P0 先行定调 → P1 概念插画 → P2 流程模板 → P3 表格排版（§2.8）
- **逐图验收**：6 条验收清单（形象一致、标注齐全、单色可读...）

- **表格**：随文表与可复印表单分开编号（表 x-y / T-xx）；表单四件套（编号标题＋表头字段行＋脚注＋示例行）；母本文件为排版权威，章内为阅读版，同步纪律入进度文件；
- **插画**：先出风格样张定调；全局风格前缀＋负面提示＋统一资产库（角色与比喻物形象全书一致）；**画面无文字是铁律**（文字标注留给设计师后期加，prompt 中登记标注位）；每张图的完整 prompt 登记进交付清单，保证可重绘；
- **批量件用模板**：章末思维导图、构件收藏卡等系列图共用一套模板 prompt，只替换内容槽。

### 阶段 5：组装管线

单脚本一键从分章 markdown 生成合并版与出版级 docx。架构、pandoc/docx 已知坑与解法见 references/pipeline.md。原则：**对源文件只读、全流程幂等、规范化在后处理层做**。

### 阶段 6–7：审计与交付

四类自动终检（断链/编号/引号/表格）＋ docx 体检＋人工审校材料包＋三方分工交付表，见 references/audit-and-handoff.md。交付时进度文件升级为"终态版"：剩余工作全部为外部依赖，AI 侧无未销项。

## Agent 工具操作注意（实测教训）

1. **大块中文内容写入**：shell heredoc 一次传超长内容易被截断——分小块（<3KB）追加，或用文件写入工具整文件落盘；写完立即 `wc -c` 校验字节数；
2. **工具调用正文避免 ASCII 直引号**：中文书稿一律用中文弯引号（""''）；直引号留给组装脚本做最后规范化兜底；
3. **大文件精确编辑**：先 `grep -n`/`sed -n` 取出精确原文再做替换；锚点不匹配时不要凭记忆猜，改用小段多次替换；
4. **沙箱路径**：脚本与命令用相对路径；部分沙箱会改写绝对路径导致 heredoc 内路径失效；
5. **改动闭环三步**：改源稿 → 重跑组装脚本 → 跑四类终检并更新进度文件版本历史；三步齐了才算一次改动完成；
6. **环境预检**：转换前确认 pandoc / python-docx / pillow 可用；系统包缺失时用 pip 可安装等价物（如 `pypandoc-binary` 自带 pandoc 二进制）；`bc`、`unzip` 等小工具常缺席，用 python 单行替代。
7. **排版即写入口径（铁律）**：写书稿时第一次就按《中文排版指北》来撰写 markdown，禁止"先随意写、事后批量修复"。每段写完立即跑排版自检脚本，退出码 0 才算干净，有问题当场改，禁止攒批返工。理由：事后修复会污染文件名扩展名（`.mmd`）、shell 记号（`kill -9`）等白名单写法，返工浪费远大于当场注意。五条高频规则：①中英文之间加空格；②中文与数字之间加空格；③全角标点前后不加空格；④Markdown 强调标记紧贴中文标点时须闭合无歧义；⑤专有名词按官方大小写。
8. **图表中文显示、宽高比与风格一致性（铁律）**：markdown 转 docx 时，所有图表中的中文必须正常显示，禁止出现不显示或方框（tofu）。做法：docx 嵌入前预栅格化为 300DPI PNG，字体链包含 CJK 回退链（Noto Sans CJK SC 优先），交付前逐图检查 `.notdef` 字形。制作图表时必须保持匀称的高宽比（单栏图 4:3～16:9），不得出现细带或竖条出厂，使用 `mmd_square.py` 自动校验。**所有插画和图表必须使用一致的风格**（线条粗细、配色方案、字体字号、圆角大小、阴影风格等），做法：全局风格前缀逐字粘贴、统一资产库、风格样张定调、每批生产完后并排目检。理由：中文方框、宽高比失调、风格不一致都会直接影响出版质量和读者体验，事后修复成本极高。
