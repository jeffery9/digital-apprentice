# 模式卡模板 · 经典族（第 5–10 章：规划 / 上下文 / 工具 / 记忆 / 反思 / 编排）

> 用法：复制下面的空表到章稿中，替换 `〈…〉`。九字段一个都不能删。

【模式卡：〈中文名〉（〈english name〉）】

| 字段 | 内容 |
| --- | --- |
| **名称** | 〈中文名〉（〈english name〉） |
| **意图** | 〈一句话，≤40 字〉 |
| **问题** | 〈什么困境下出现。写到读者能认出自己的系统为止〉 |
| **结构** | 〈组成部件与关系。必须能照着写出代码骨架〉 |
| **适用场景** | 〈可判定的具体条件〉 |
| **不适用场景** | 〈什么条件下用它是错的〉**＋本族必答：推理模型（长思维链）把哪一部分吸收进模型内部了？这个模式还成立吗？成立的理由是什么？** |
| **风险与代价** | 〈付出什么、以什么形态出故障〉**＋本族必答：与"不做这件事"相比，净收益在什么条件下为负？** |
| **关联模式** | 〈同族／跨族关联，逐个标章号〉 |
| **出处与实例** | 〈论文或开源系统，带年份〉；〈智航案例中的具体情节〉 |

## 本族填写注意

1. **"推理模型吸收了它吗"是本族的核心判断题。** 2024 年成立的模式，到 2026 年有一部分已经被模型内部能力吸收（典型：显式的思维链提示、简单的自我批评）。写不出这个判断，说明卡的时效性没想清楚。
2. **结构字段要写到"能照着写代码"。** 本书有 20 个 demo，每张经典族卡最好能指到某个 demo 或某段伪代码。
3. **智航实例必须具体到情节**（"工单 agent 在第三步走偏"），不能写"某企业实践中"。案例是虚构的，但情节必须可信、可追溯到章节总表的七阶段旅程。
