## 一、一句话定位

**面向架构师与技术决策者的 AI Agent 架构深潜书：框架无关、模式目录化、决策科学化——不讲"怎么搭一个 agent"，讲"为什么这样设计、怎么权衡、什么时候不该用"。**

电梯陈述：市面上教人"搭 agent"的书已经很多，教人"为 agent 系统做架构决策"的书几乎没有。本书把三年 agent 工程实践浓缩为一张五层参考架构总图（含模型接入半层与贯穿全层的模态轴）、约五十张 GoF 风格设计模式卡、十八个可运行的关键 demo，和一整套可复用的决策工具（选型矩阵、ADR 模板、上线检查清单）。读完这本书，你交付的不只是代码，还有能让 CEO 和团队信服的架构决策记录。

与前作的关系：《数字见习生》回答"AI agent 是什么、普通人怎么用"；本书回答"agent 系统怎么设计、技术负责人怎么决策"。两书独立成篇，可在前言/封底互相引荐，形成"使用者入门＋构建者深潜"双书矩阵。

## 二、时机判断（为什么是现在写）

1. **技术面从炒作期进入收敛期，第一次有了"值得写进书里"的稳定对象。** 协议层是最强信号：MCP 以约 9700 万下载量赢下 agent-工具层，Anthropic/OpenAI/Google/Microsoft 全部采纳，已入 Linux Foundation；A2A 进入 Linux Foundation 一年后（2026-04）汇聚 150+ 组织、落地主要云平台并进入企业生产（来源见§十三，下同）。2026 被业界称为"协议收敛之年"——收敛意味着可以写"格局与边界"，而不只是追逐新闻。
2. **模型层仍在剧烈变化，恰恰需要一本讲"不变量"的书。** 框架年年换、模型季季换，但循环本质、上下文经济学、分布式系统类比、安全原理这些 L1 层知识的半衰期在五年以上。本书的时效分层策略（§九）正面解决这个问题。
3. **中文出版空窗。** 中文世界目前唯一的系统性同类作品是免费在线书（绑定作者自家开源项目，非出版物）；Gulli 的《Agentic Design Patterns》中译本走百科式动手路线且非决策导向。**"中文纸质 × 架构师决策视角"这个位置现在没人占。**
4. **读者基数已成型。** 2024-2026 三年间大量后端/平台工程师被推上 agent 项目，其中先进者正在晋升为"agent 架构决策者"——他们买书不是为了入门，是为了做对决策、说服别人。
5. **两个新维度在 2026 年恰好从"功能特性"变成了"架构问题"（v0.1 新增判断）。**
   - **多模态**：模型的模态支持已经矩阵化（图像/文档/音频/视频/屏幕），生产瓶颈随之从"模型能不能看"转移到"感知管线怎么切、模态上下文怎么计价、多模态注入怎么防、跨模态记忆怎么存"。computer use 是这条线最尖锐的例子——基准分数逐年走高，但真实长程工作流的成功率仍显著低于基准，且"截图-思考-行动"循环对动态界面存在结构性限制（OSWorld 2.0，2026-06）。这种"能力有余、可靠性不足"的落差，正是需要架构判断而非功能罗列的时刻。
   - **多模型**：供应商限流与宕机、成本压力、数据驻留合规、开源权重小模型成熟，四股力量叠加，使"模型池＋网关＋路由"在 2026 年成为默认基础设施形态（AI 网关产品同年集中成熟并被企业采购目录收录）。架构师必须为它做治理决策——谁批准接入新模型、能力画像谁维护、降级到什么、退出成本多少——而不是让每个服务各自硬编码一个模型。
   - 两个维度的共同点：**它们都不是"再加一章新技术"，而是要改写参考架构本身**。所以 v0.1 把它们做进总图（L1b 半层＋模态横切轴），而不是塞进"前沿实践"散章——这正是竞品目前的处理方式，也是本书的差异化。

## 三、目标读者

### 画像 P1：平台架构师 / 技术总监（首要读者，全书为 TA 而写）
- 35±5 岁，管 5-20 人团队，公司正要上 agent 项目或已有雏形失控
- 痛点：要决定自研还是用框架、单 agent 还是多 agent、要不要接 MCP、**用几个模型和要不要建网关、要不要上多模态**；要给 CEO 写方案、给团队定规范；网上资料碎片化且互相矛盾
- 从本书获得：参考架构、模式目录、决策框架、ADR 模板——**能直接带去开架构评审会的东西**

### 画像 P2：资深工程师转型 AI 工程（次要读者）
- 会写代码、懂分布式，缺 agent 领域的系统地图
- 从本书获得：从循环本质到生产治理的完整知识骨架，demo 代码可上手复现

### 画像 P3：技术顾问 / 解决方案架构师（次要读者）
- 为客户做 agent 方案设计与评审
- 从本书获得：选型维度、风险清单、反模式目录——评审别人的方案时最好用

### 非目标读者（书里明说，避免错配差评）
- 零编程基础读者 → 请读《数字见习生》
- 只想 30 分钟跑通一个 demo 的尝鲜者 → 框架官方 quickstart 更快
- 前沿研究者 → 本书引用论文但不做学术综述
- **想学多模态模型本身（训练/微调 VLM、语音模型）的读者 → 本书只讲多模态的系统架构，不讲模型内部**（v0.1 新增，避免错配）

### 前置要求
- 熟练的编程经验（任何语言）；了解 HTTP/JSON/数据库等工程常识
- LLM 使用经验（调过任一聊天 API 即可）；**不要求**了解任何 agent 框架，**不要求**了解多模态模型

### 本书差异化五支柱
1. **决策科学视角**：每章以真实决策场景开场、以决策指引收尾（何时用/何时不用/风险清单/权衡表）；贯穿案例"智航科技"（§六）让 18 章的决策连成一家公司的完整旅程。
2. **模式卡片目录**：GoF 风格的约 50 张模式卡（意图/结构/适用/不适用/风险/关联模式/实例），附录 A 总成速查目录——中文纸质书里独一份。
3. **时效分层机制**：内容按半衰期分 L1/L2/L3 三层并显式标注，L3 事实全部带"截至 2026-10"锚点＋配套页面承接更新（§九）。这是《数字见习生》时效体检经验的升级版，也是所有竞品都没做的。
4. **纸书级图表体系**：一张五层参考架构总图贯穿全书，每章放大一块；模式结构图＋时序图约 70 幅，Mermaid/SVG 精确制图（非 AI 插画），印刷质量可控。
5. **模态与模型池的架构化（v0.1 新增）**：把"多模态"从功能清单讲成**横切架构维度**（模态轴：它同时改写 L1 的能力探测、L2 的上下文预算、L3 的感知管线、L5 的评估与安全），把"多模型"从省钱技巧讲成 **L1b 接入层的治理问题**（能力画像、网关、路由分层、降级矩阵、供应商退出成本、合规驻留）。竞品把这两件事放在"前沿实践"或"成本优化"里，本书把它们放进参考架构——因为架构师真正要拍板的是后者。

## 六、内容主线与结构逻辑

### 三部结构：认知 → 模式 → 决策

```
第一部 认知与基础（第1-4章）    建立共同语言：agent 是什么、系统长什么样、
                              模型层（单个模型的能力 ＋ 一群模型的接入）如何制约架构
第二部 设计模式深潜（第5-13章）  九章九个模式族，全书主体：规划/上下文/工具/记忆/
                              反思/编排/多智能体/协议/多模态
第三部 生产与决策（第14-18章）   架构师的职场：运行时与安全、评估、成本、选型与组织落地
附录 A-E                        模式速查目录、术语表、决策工具箱、时效说明、延伸阅读
```

结构逻辑对应架构师的真实工作流：**先看懂系统（认知）→ 再掌握机制（模式）→ 最后做出决策并为之负责（生产与决策）**。第二部按"五层参考架构"逐层放大，第三部把治理层与横切决策收拢。

**v0.1 的两处结构变化及其理由：**
- **模型接入层前置到第一部（新第4章）**：它与第3章"单个模型的能力"是同一层（L1）的两半——先讲"模型能做什么"，紧接着讲"一群模型怎么接、怎么选、怎么降级"。放第一部是因为架构师在项目第一周就要做这个决定，且后续所有章节（上下文预算、工具调用格式、评估、成本）都以"存在模型池与网关"为前提。
- **多模态放在第二部收尾（新第13章）**：多模态是横切维度而非独立一层，讲它需要读者已具备上下文工程（第6章）、工具架构（第7章）、记忆（第8章）、事件驱动编排（第10章）、沙箱（概念上第14章的前置认知）与协议（第12章）的全部词汇。放在第二部末尾，既是"能力扩展"的自然收束，也能一次性把前八章的模式在模态轴上重演一遍。

### 贯穿案例："智航科技"（虚构，B2B 客服/工单 SaaS 厂商，约 200 人）
每章开篇的决策场景与章末的"架构师视角"回应当都取自同一家公司的 agent 化六阶段旅程：

```
客服副驾与模型接入整顿 → 自主工单 agent → 平台化·多 agent·协议 → 多模态扩展 → 生产事故与治理 → 年度架构评审
     （第1-4章）          （第5-9章）        （第10-12章）        （第13章）      （第14-17章）      （第18章）
```

案例中承接两大新维度的具体情节（均为虚构）：三套 agent 各自硬编码了一个供应商，某次上游限流导致全线停摆，同时 CFO 质问"为什么一个分类任务也在用旗舰模型"（第4章）；客户开始上传报错截图、合同扫描件与呼叫中心录音，只会读文本的工单 agent 哑火，而安全团队同时提出了"图片里也可能藏指令"的质疑（第13章，并回接第15章安全）。

案例数据全部虚构并首次出现时声明，规避事实风险；它给本书提供竞品都没有的**决策叙事连贯性**。

### 五层参考架构总图（全书之锚，本书综合提出，非业界标准，书中如实声明）

```
                          ┌────────────────────────────────────┐
   模态轴（横切 L1-L5）→   │ 文本 · 图像 · 文档 · 音频 · 视频 · 屏幕 │
                          └────────────────────────────────────┘
┌──────────────────────────────────────────────────────────────┐
│ L5 治理层   安全 · 评估 · 可观测 · 成本 · 合规                  │ ← 第三部
├──────────────────────────────────────────────────────────────┤
│ L4 编排层   循环 · 状态机 · 多agent拓扑 · 协议(MCP/A2A)         │ ← 第10-12章
├──────────────────────────────────────────────────────────────┤
│ L3 能力层   工具 · 执行环境 · 沙箱 · 感知管线 · computer use    │ ← 第7、13、14章
├──────────────────────────────────────────────────────────────┤
│ L2 上下文层  工作上下文 · 记忆 · 检索 · 压缩 · 模态预算          │ ← 第6、8章
├──────────────────────────────────────────────────────────────┤
│ L1 模型层                                                      │
│   L1a 模型能力  推理 · 工具调用机制 · 上下文窗口 · 模态支持       │ ← 第3章
│   L1b 模型接入  网关 · 能力画像 · 路由 · 级联 · 故障转移 · 驻留    │ ← 第4章
└──────────────────────────────────────────────────────────────┘
```

**v0→v0.1 总图变更说明（书中会如实交代这个建模选择）：**
- 层数仍是**五层**，不新增第六层——避免动摇"全书之锚"，也避免读者把它误当成又一套新框架。
- **L1 内部分为 a/b 两半**：能力（模型是什么）与接入（模型怎么用）。这一刀切的是"变化频率"——L1a 随模型代际变化，L1b 随组织结构与供应商关系变化，两者的治理主体和复核周期都不同。
- **模态是横切轴，不是一层**：多模态在每一层都留下痕迹（L1a 支持哪些模态、L2 非文本信息怎么表示与计价、L3 感知管线与屏幕动作循环、L5 多模态评估与注入防御）。把它画成层会误导读者以为"多模态是一个可以外包的模块"，而它实际上是贯穿性的架构约束。

#### 第4章 模型接入层：模型池、网关与能力路由（v0.1 新增）
- 4.1 决策场景：智航的三套 agent 各自硬编码了一个供应商；一次上游限流让全线停摆，CFO 同时质问"为什么一个分类任务也在用旗舰模型"
- 4.2 从"一个模型"到"模型池"：为什么生产系统的默认形态是模型组合——四股驱动力（能力异构、成本异构、供应商风险、合规与驻留分区）；L1b 半层的由来
- 4.3 **能力画像（capability profile）**：把模型当"有规格的组件"管理——上下文窗口/工具调用格式与并行调用支持/结构化输出可靠性/模态输入输出/推理模式与思维链预算/延迟与吞吐/单价（含缓存价）/许可与数据驻留/弃用周期。画像既是路由的输入，也是选型的输出，还是回归测试的基线
- 4.4 **模型网关（gateway）架构**：单一入口、供应商 API 归一化、**模型快照固定（snapshot pinning）**、租户配额与预算、密钥托管、集中策略、按路由遥测——网关 vs 应用内薄适配层（`llm.py`）的分工与演进路径（什么时候适配层就够、什么时候必须上网关）
- 4.5 **路由的四类策略与分层组合**：规则路由（可调试、覆盖窄）／语义（嵌入）路由（覆盖长尾、需阈值与漂移监控）／预测（分类器）路由（精度最高、需大量标注与延迟税）／级联（生成后）路由（绕开"预测难度"这个最难的问题，代价是升级请求双跑）。生产系统的收敛形态是**分层叠加**而不是单选；并给出"什么时候才配得上学习式路由"的数据门槛
- 4.6 **路由的三个目标、三种度量**：韧性路由（成功率/故障期间可用性）、成本路由（单位任务成本，且必须含重试与级联双跑）、质量路由（评估驱动，需评估层垫底，呼应第16章）——目标混淆是最常见的路由失败根因
- 4.7 **Agent 场景的路由特殊性**：一次用户回合 = 多次模型调用（规划/工具选择/摘要/生成/判官），**每个调用点独立路由**；只优化第一跳约等于只优化两成开销；调用点级路由表的设计与治理
- 4.8 **故障转移与降级**：熔断阈值与退避、幂等重放、跨供应商降级的真实代价（换模型＝换工具调用格式、换系统提示行为、换缓存命中，**降级不是改个模型名**）；降级矩阵的写法
- 4.9 **供应商锁定与退出成本**：抽象层能抽象掉什么、抽象不掉什么（提示词与模型的行为耦合、工具调用风格、结构化输出行为、思维链预算、缓存前缀）；退出成本的量化方法与"可移植性预算"
- 4.10 **合规与数据驻留路由**：受监管数据走本地/私有部署模型的策略位置（应在网关策略层第一天写入，而非事后补）；开源权重与小模型（SLM）的能力-成本-主权三角【L3 锚点】
- 4.11 **模型弃用与代际更替的运行手册**：版本快照、影子评估（shadow eval）、灰度切换、回滚门槛——把"换模型"从项目变成一次普通变更（与 3.6 呼应，此处给流程）
- 4.12 路由的反模式：没有生产日志就上学习式路由、只看单价不看总成本、缓存放在路由之后、路由逻辑散落在各服务、把熔断当重试、为"未来可能的多模型"提前建网关
- 模式卡：**能力画像路由／语义路由／级联升级／模型网关／故障转移与熔断**（5 张，v0.1 新增"模型编排与路由"模式族）
- Demo D-03：规则／语义／级联三种路由策略在同一任务集上的**成本-质量-延迟三维对比**（含"只路由第一跳 vs 全调用点路由"的开销差异实测）；Demo D-04：最小模型网关——快照固定＋故障转移＋熔断＋按路由遥测，约 80 行，被后续 demo 复用
- 图：**模型池与网关架构图（本章之锚）**；路由四策略决策树；调用点级路由表；降级矩阵；质量-成本前沿曲线；能力画像表样式

#### 第13章 多模态 Agent 架构：感知、语音与 computer use（v0.1 新增）
- 13.1 决策场景：智航的客户开始上传报错截图、合同扫描件和呼叫中心录音，只会读文本的工单 agent 哑火；CTO 问"是不是换个多模态模型就行了"，安全团队同时提出"图片里也可能藏指令"
- 13.2 **模态是横切维度，不是一层**：多模态在 L1a（模型原生支持哪些模态、支持到什么可靠性）／L2（非文本信息在上下文里怎么表示、占多少预算）／L3（感知管线、computer use 的屏幕动作循环）／L5（多模态评估与注入防御）上各自的含义——模态轴总图导读
- 13.3 **两种根本架构**：原生多模态模型（单一模型端到端）vs 感知-推理分离管线（专用编码器/OCR/ASR/检测器 → 中间表示 → 语言模型推理）；四个维度的对照（可靠性、单位成本、可观测性、组件可替换性）；为什么生产系统通常是混合，以及混合的切分线画在哪
- 13.4 **模态归一化与中间表示**：把图像/音频/视频转成"语言模型能可靠消费的东西"——文本化、结构化 JSON、标注帧、切片与采样；**中间表示即架构契约**（可单测、可缓存、可回放、可脱敏），以及"过早文本化丢失了什么"的清单
- 13.5 **视觉即工具（vision-as-tool）**：不给主模型装眼睛，而是给它一个"看"的工具（截图→描述/OCR/元素定位/坐标返回）；与原生 VLM 的分工判据；上下文预算、可复用性、可降级性三笔账（承接 7.3 工具粒度、7.7 感知类工具）
- 13.6 **多模态上下文经济学**：图像按分块与分辨率计价、音频按时长计价、视频按帧采样计价——**不同模态的 token 经济学可差一个数量级**；分辨率-成本-准确率的三选二；"把文档当图像读有时比当文本读更省"这类反直觉结论的适用边界与自证方法【L3 锚点】
- 13.7 **文档理解管线**：解析器/OCR 路线 vs 视觉检索路线（ColPali 一系，跳过 OCR 直接对页面做视觉编码）vs 混合；表格、版式、跨页引用的三类失真点；多模态 RAG 的架构选型（承接 6.6 检索增强、8.7 跨模态记忆）
- 13.8 **语音与实时交互架构**：事件驱动管线（ASR/LLM/TTS 与感知处理器并发流）、传输层决定能力上限（WebRTC 与帧率/抖动）、轮次检测与打断（turn-taking/barge-in）、延迟预算分解（端到端可接受阈值与各段配额）、语音 agent 的评估指标为何与文本 agent 不同（承接 10.4 状态机编排）
- 13.9 **computer use 与 GUI agent**：屏幕-动作循环的结构、可靠性现状（基准分数与真实长程工作流成功率的落差）、"截图-思考-行动"循环面对动态界面的结构性限制【L3 锚点】；判定：什么时候用 computer use、什么时候改造出 API、什么时候用专用工具（原 v0 的 12.5 移入此处）
- 13.10 **输出模态**：语音合成、图像与图表生成、文档产出进入 agent 循环——生成物的校验方式、工件（artifact）管理与版本、版权与合规位、"输出模态也是攻击面"
- 13.11 **多模态记忆与检索**：跨模态记忆的三种表示（原始引用/描述文本/嵌入）与其检索一致性；存储成本与生命周期；人脸、声纹、位置一类生物识别与敏感模态的特殊合规位（承接 8.4、8.6）
- 13.12 **多模态失败模式与安全**：**图像/PDF/音频里的提示注入**——文本护栏对多模态攻击基本失明，OCR 产物与原生视觉输入的信任级别并不相同；多模态幻觉（图表误读、版式臆测、无中生有的字段）；模态降级攻击（把关键指令藏在低置信通道）；对策在架构层的位置（承接第15章，此处给模态特有部分）

## 八、写作风格与体例规范

### 章节骨架（八段式，全书统一）
1. **决策场景**（智航案例，300-500 字）——问题先行
2. **本章地图**（一段话＋小节导航）
3. **原理深潜**（主体，机制讲到 token/消息/状态级别，但用架构师语言）
4. **模式卡**（穿插或集中于章中，格式见下）
5. **架构图**（每章 3-7 幅）
6. **关键 demo**（如有：讲解＋核心代码＋"观察什么"）
7. **决策指引**（何时用/何时不用/风险清单/权衡表——本章的可带走资产）
8. **架构师视角盒**（1-2 个）＋小结＋延伸阅读（3-5 条带一句话评注）

### 模式卡格式（九字段，全书约 50 张）
名称（中英）｜意图（一句话）｜问题（什么困境下出现）｜结构（小图）｜适用场景｜**不适用场景**（竞品普遍缺失的字段）｜风险与代价｜关联模式｜出处与实例（论文/开源系统/智航案例，带年份）

### 语言与术语
- 中文为主，术语首次出现给中英对照（如"上下文压缩（compaction）""能力画像（capability profile）""模态归一化（modality normalization）"），此后中文为主；附录 B 统一
- 语气：资深架构师对同行讲话——直接、有观点、敢下判断；判断必须给理由和边界
- 有观点但不站队：对争议（如多 agent 论战、原生多模态 vs 感知管线）呈现双方最强论点后给本书判定
- 禁用营销话术（"革命性""颠覆"）；数字必须带来源与日期
- **同名不同物必须显式辨析（v0.1 新增）**：如"路由"一词在工作流编排与模型选择两个语境下含义不同，首次共现处必须辨析并在附录 B 立条

### 代码规范（混合策略的具体化）
- 全书 18 个关键 demo（§十），每个 ≤150 行核心代码，书中展示骨干片段＋完整代码入配套仓库
- 正文以架构图、时序图、伪代码为主；伪代码语言中立
- 所有代码不绑定商业框架（直调模型 API），模型通过薄适配层可替换
- 代码块标注语言与"该片段在 demo 仓库中的文件路径"
- **多模态与路由类 demo 的额外约定（v0.1 新增）**：必须提供 `--mock` 离线模式（无网络、无 API key 也能跑通全流程，用录制回放或本地替身），否则读者无法复现，编辑也无法审校

### 图表规范
- 三类图：总图放大系（源自第2章五层总图，v0.1 含 L1a/L1b 与模态轴两个新放大方向）、模式结构图（UML 风格）、时序/流程图
- 工具链：Mermaid 源稿（入库、可 diff、可再生）→ SVG 导出 → docx 嵌入；印刷前统一风格审查
- 概念性章首图可用 AI 插画（复用《数字见习生》插画管线经验），技术图一律精确制图
- 图编号按章（图 4-1），表同（表 4-1）；每图必有图题与一句话导读
- **多模态章的图像素材须遵守 13 章"素材纪律"，且印刷为黑白时需自检可辨识（不依赖颜色区分模态）**（v0.1 新增）

### 事实纪律（沿用并升级《数字见习生》纪律）
- 占位事实用【方括号】，读者填写位用下划线（本书预计极少）
- 外部数据三要素：数字＋来源＋日期；来源集中在附录 E 与各章延伸阅读
- 虚构声明：智航科技案例首次出现处声明虚构；任何与真实公司的相似为巧合
- **多模态素材的来源与授权链须留档台账（自制/授权/公有领域三选一，禁止来历不明截图）**（v0.1 新增）

## 九、时效策略：内容半衰期分层（本书的核心工程创新）

agent 领域的时效衰减比《数字见习生》面对的快一个数量级，故把时效治理从"机制补丁"升级为"内容架构"：

| 层 | 内容 | 半衰期 | 占比目标 | 处理方式 |
| --- | --- | --- | --- | --- |
| **L1 原理层** | 循环本质、上下文经济学、安全原理、分布式类比、**路由与降级的策略学**、**感知-推理分离与中间表示契约**、决策方法论 | 5 年＋ | ~62% | 全书主体，正常写作 |

- 配套页面承诺：附录 D 给出配套页面信息块（复用《数字见习生》C-4 信息块体例），承诺 L3 层的季度更新；托管方待定（外部依赖）
