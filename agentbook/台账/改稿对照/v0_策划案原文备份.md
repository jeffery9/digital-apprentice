## 一、一句话定位

**面向架构师与技术决策者的 AI Agent 架构深潜书：框架无关、模式目录化、决策科学化——不讲"怎么搭一个 agent"，讲"为什么这样设计、怎么权衡、什么时候不该用"。**

电梯陈述：市面上教人"搭 agent"的书已经很多，教人"为 agent 系统做架构决策"的书几乎没有。本书把三年 agent 工程实践浓缩为一张五层参考架构总图、约四十张 GoF 风格设计模式卡、十五个可运行的关键 demo，和一整套可复用的决策工具（选型矩阵、ADR 模板、上线检查清单）。读完这本书，你交付的不只是代码，还有能让 CEO 和团队信服的架构决策记录。

与前作的关系：《数字见习生》回答"AI agent 是什么、普通人怎么用"；本书回答"agent 系统怎么设计、技术负责人怎么决策"。两书独立成篇，可在前言/封底互相引荐，形成"使用者入门＋构建者深潜"双书矩阵。

## 二、时机判断（为什么是现在写）

1. **技术面从炒作期进入收敛期，第一次有了"值得写进书里"的稳定对象。** 协议层是最强信号：MCP 以约 9700 万下载量赢下 agent-工具层，Anthropic/OpenAI/Google/Microsoft 全部采纳，已入 Linux Foundation；A2A 进入 Linux Foundation 一年后（2026-04）汇聚 150+ 组织、落地主要云平台并进入企业生产（来源见§十三，下同）。2026 被业界称为"协议收敛之年"——收敛意味着可以写"格局与边界"，而不只是追逐新闻。
2. **模型层仍在剧烈变化，恰恰需要一本讲"不变量"的书。** 框架年年换、模型季季换，但循环本质、上下文经济学、分布式系统类比、安全原理这些 L1 层知识的半衰期在五年以上。本书的时效分层策略（§九）正面解决这个问题。
3. **中文出版空窗。** 中文世界目前唯一的系统性同类作品是免费在线书（绑定作者自家开源项目，非出版物）；Gulli 的《Agentic Design Patterns》中译本走百科式动手路线且非决策导向。**"中文纸质 × 架构师决策视角"这个位置现在没人占。**
4. **读者基数已成型。** 2024-2026 三年间大量后端/平台工程师被推上 agent 项目，其中先进者正在晋升为"agent 架构决策者"——他们买书不是为了入门，是为了做对决策、说服别人。

## 三、目标读者

### 画像 P1：平台架构师 / 技术总监（首要读者，全书为 TA 而写）
- 35±5 岁，管 5-20 人团队，公司正要上 agent 项目或已有雏形失控
- 痛点：要决定自研还是用框架、单 agent 还是多 agent、要不要接 MCP；要给 CEO 写方案、给团队定规范；网上资料碎片化且互相矛盾
- 从本书获得：参考架构、模式目录、决策框架、ADR 模板——**能直接带去开架构评审会的东西**

### 画像 P2：资深工程师转型 AI 工程（次要读者）
- 会写代码、懂分布式，缺 agent 领域的系统地图
- 从本书获得：从循环本质到生产治理的完整知识骨架，demo 代码可上手复现

### 画像 P3：技术顾问 / 解决方案架构师（次要读者）
- 为客户做 agent 方案设计与评审
- 从本书获得：选型维度、风险清单、反模式目录——评审别人的方案时最好用

### 非目标读者（书里明说，避免错配差评）
- 零编程基础读者 → 请读《数字见习生》
- 只想 30 分钟跑通一个 demo 的尝鲜者 → 框架官方 quickstart 更快
- 前沿研究者 → 本书引用论文但不做学术综述

### 前置要求
- 熟练的编程经验（任何语言）；了解 HTTP/JSON/数据库等工程常识
- LLM 使用经验（调过任一聊天 API 即可）；**不要求**了解任何 agent 框架

### 本书差异化四支柱
1. **决策科学视角**：每章以真实决策场景开场、以决策指引收尾（何时用/何时不用/风险清单/权衡表）；贯穿案例"智航科技"（§六）让 16 章的决策连成一家公司的完整旅程。
2. **模式卡片目录**：GoF 风格的约 40 张模式卡（意图/结构/适用/不适用/风险/关联模式/实例），附录 A 总成速查目录——中文纸质书里独一份。
3. **时效分层机制**：内容按半衰期分 L1/L2/L3 三层并显式标注，L3 事实全部带"截至 2026-10"锚点＋配套页面承接更新（§九）。这是《数字见习生》时效体检经验的升级版，也是所有竞品都没做的。
4. **纸书级图表体系**：一张五层参考架构总图贯穿全书，每章放大一块；模式结构图＋时序图约 60 幅，Mermaid/SVG 精确制图（非 AI 插画），印刷质量可控。

## 六、内容主线与结构逻辑

### 三部结构：认知 → 模式 → 决策

```
第一部 认知与基础（第1-3章）    建立共同语言：agent 是什么、系统长什么样、模型层如何制约架构
第二部 设计模式深潜（第4-11章）  八章八个模式族，全书主体：规划/上下文/工具/记忆/反思/编排/多智能体/协议
第三部 生产与决策（第12-16章）   架构师的职场：运行时与安全、评估、成本、选型与组织落地
附录 A-E                        模式速查目录、术语表、决策工具箱、时效说明、延伸阅读
```

结构逻辑对应架构师的真实工作流：**先看懂系统（认知）→ 再掌握机制（模式）→ 最后做出决策并为之负责（生产与决策）**。第二部按"五层参考架构"逐层放大，第三部把治理层与横切决策收拢。

### 贯穿案例："智航科技"（虚构，B2B 客服/工单 SaaS 厂商，约 200 人）
每章开篇的决策场景与章末的"架构师视角"回应当都取自同一家公司的 agent 化五阶段旅程：
客服副驾（第一部）→ 自主工单 agent（第4-8章）→ 平台化与多 agent（第9-11章）→ 生产事故与治理（第12-15章）→ 年度架构评审（第16章）。
案例数据全部虚构并首次出现时声明，规避事实风险；它给本书提供竞品都没有的**决策叙事连贯性**。

## 七、详细大纲

> 每章固定骨架（详见§八）：决策场景（智航案例）→ 原理深潜 → 模式卡 → 架构图 → 关键 demo → 决策指引 → 章末小结。以下按章列出节级结构与配套资产。

### 第一部 认知与基础

#### 第1章 Agent 是什么：能力边界与架构第一性原理
- 1.1 决策场景：智航科技该不该把客服机器人"升级成 agent"
- 1.2 光谱：固定 workflow → 带选择的 workflow → agent（自主循环）——延续 Anthropic《Building Effective Agents》的分类学并给出 2026 视角的修订
- 1.3 循环的第一性原理：模型＋工具＋上下文＋停止条件，四要素缺一不可
- 1.4 能力-成本-可靠性三角：为什么 agent 是"用可靠性换自主性"的交易
- 1.5 什么时候**不**该用 agent：决策树（任务可预先编排吗？错误代价可承受吗？延迟预算够吗？）
- 1.6 agent 与相邻概念的边界：chatbot、RAG 应用、RPA、传统分布式 worker
- 模式卡：增强型 LLM（augmented LLM，基础构件）／Agent 循环／Workflow-Agent 光谱定位
- Demo D-01：30 行最小 agent 循环（Python 直调 API，不用任何框架）——证明"agent 是循环，不是魔法"
- 图：能力-成本-可靠性三角；agent 判定决策树；循环四要素图
- 架构师视角盒：①"demo 惊艳、生产翻车"的根因清单 ②向 CEO 解释 agent 风险的三分钟话术

#### 第2章 参考架构：五层解剖一个 agent 系统
- 2.1 决策场景：智航的三套 agent 各行其是，CTO 要求画出统一架构图
- 2.2 五层参考架构总图逐层导读（L1 模型能力 / L2 上下文 / L3 能力 / L4 编排 / L5 治理）——全书总图在此登场，后续每章放大一块
- 2.3 控制流与数据流：一次任务的完整生命周期（时序图）
- 2.4 状态在哪里：agent 系统的状态机本质，与传统微服务/工作流引擎的对照
- 2.5 边界与接口：五层之间应该怎么切、切错的代价
- 2.6 参考架构的使用方法：它是词汇表和检查清单，不是必须照抄的蓝图
- 图：**五层总图（全书之锚）**；任务生命周期时序图；与微服务架构的对照表图
- 架构师视角盒：①用五层图给存量系统做体检 ②架构图评审时最常被问的五个问题

#### 第3章 模型能力层：模型演进如何改写架构
- 3.1 决策场景：智航要不要为"更强的新模型"重构 agent
- 3.2 工具调用到底怎么发生：function calling 的 token 级机制、结构化输出的约束解码——祛魅
- 3.3 推理模型（长思维链、交错思考）对编排的改写：哪些模式被吸收进模型、哪些反而更重要
- 3.4 上下文窗口的真相：容量 ≠ 有效性，长上下文衰减（context rot）与架构对策
- 3.5 多模态与 computer use 能力对 L3 层的影响（概览，详见第12章）
- 3.6 模型代际更替的对冲策略：能力探测、抽象层、"哪些决策不要押注模型进步"
- 模式卡：结构化输出守卫（schema 约束＋校验重试）
- Demo D-02：结构化输出 vs 文本解析的可靠性对比实验（同一任务 100 次运行的成功率统计）
- 图：function calling 机制时序图；"模型进步吸收了什么/留下了什么"对照图
- 时效注意：本章 L3 内容最多，全部打"截至 2026-10"锚点
- 架构师视角盒：①换模型的回归成本清单 ②模型供应商锁定风险评估

### 第二部 设计模式深潜（八章八个模式族）

#### 第4章 规划模式：任务分解与重规划
- 4.1 决策场景：智航的工单 agent 在第三步就走偏了，谁来纠偏
- 4.2 ReAct：思考-行动-观察循环的原理、轨迹解剖、失效模式（循环打转、过早行动）
- 4.3 Plan-and-Execute：先规划后执行——计划质量决定上限，重规划触发器设计
- 4.4 动态规划（plan-as-you-go）：推理模型时代的"隐式规划"，显式计划还剩什么价值
- 4.5 搜索式规划：Tree-of-Thoughts、LATS——什么时候值得为规划付指数级 token
- 4.6 规划器-执行器分离：最常见的过度设计，以及它真正正确的三个场景

## 八、写作风格与体例规范

### 章节骨架（八段式，全书统一）
1. **决策场景**（智航案例，300-500 字）——问题先行
2. **本章地图**（一段话＋小节导航）
3. **原理深潜**（主体，机制讲到 token/消息/状态级别，但用架构师语言）
4. **模式卡**（穿插或集中于章中，格式见下）
5. **架构图**（每章 3-6 幅）
6. **关键 demo**（如有：讲解＋核心代码＋"观察什么"）
7. **决策指引**（何时用/何时不用/风险清单/权衡表——本章的可带走资产）
8. **架构师视角盒**（1-2 个）＋小结＋延伸阅读（3-5 条带一句话评注）

### 模式卡格式（九字段，全书约 40 张）
名称（中英）｜意图（一句话）｜问题（什么困境下出现）｜结构（小图）｜适用场景｜**不适用场景**（竞品普遍缺失的字段）｜风险与代价｜关联模式｜出处与实例（论文/开源系统/智航案例，带年份）

### 语言与术语
- 中文为主，术语首次出现给中英对照（如"上下文压缩（compaction）"），此后中文为主；附录 B 统一
- 语气：资深架构师对同行讲话——直接、有观点、敢下判断；判断必须给理由和边界
- 有观点但不站队：对争议（如多 agent 论战）呈现双方最强论点后给本书判定
- 禁用营销话术（"革命性""颠覆"）；数字必须带来源与日期

### 代码规范（混合策略的具体化）
- 全书 15 个关键 demo（§十），每个 ≤150 行核心代码，书中展示骨干片段＋完整代码入配套仓库
- 正文以架构图、时序图、伪代码为主；伪代码语言中立
- 所有代码不绑定商业框架（直调模型 API），模型通过薄适配层可替换
- 代码块标注语言与"该片段在 demo 仓库中的文件路径"

### 图表规范
- 三类图：总图放大系（源自第2章五层总图）、模式结构图（UML 风格）、时序/流程图
- 工具链：Mermaid 源稿（入库、可 diff、可再生）→ SVG 导出 → docx 嵌入；印刷前统一风格审查
- 概念性章首图可用 AI 插画（复用《数字见习生》插画管线经验），技术图一律精确制图
- 图编号按章（图 4-1），表同（表 4-1）；每图必有图题与一句话导读

### 事实纪律（沿用并升级《数字见习生》纪律）
- 占位事实用【方括号】，读者填写位用下划线（本书预计极少）
- 外部数据三要素：数字＋来源＋日期；来源集中在附录 E 与各章延伸阅读
- 虚构声明：智航科技案例首次出现处声明虚构；任何与真实公司的相似为巧合

## 九、时效策略：内容半衰期分层（本书的核心工程创新）

agent 领域的时效衰减比《数字见习生》面对的快一个数量级，故把时效治理从"机制补丁"升级为"内容架构"：

| 层 | 内容 | 半衰期 | 占比目标 | 处理方式 |
| --- | --- | --- | --- | --- |
| **L1 原理层** | 循环本质、上下文经济学、安全原理、分布式类比、决策方法论 | 5 年＋ | ~65% | 全书主体，正常写作 |
| **L2 模式层** | 设计模式、架构风格、拓扑、评估方法 | 2-5 年 | ~28% | 模式卡出处栏记录提出年份，便于读者判断演化 |
| **L3 事实层** | 协议版本与采纳数字、框架格局、模型能力现状、法规 | 6-18 个月 | ~7% | **集中收纳**（每章独立小节，不散落正文）＋显式锚点 |

- L3 锚点标记语法：`【时效锚点｜截至 2026-10】`，正文可见（读者知道哪些内容会过期、过期去哪查）
- 附录 D 汇总全书 L3 锚点成表——读者半年后重读时可逐项核对
- 配套页面承诺：附录 D 给出配套页面信息块（复用《数字见习生》C-4 信息块体例），承诺 L3 层的季度更新；托管方待定（外部依赖）
- 写作纪律：任何论断若依赖 L3 事实，必须同时给出"L3 失效后论断如何降级"的写法（例："MCP 是当前工具层事实标准【锚点】；即便未来出现替代协议，本章的防腐层模式依然成立"）
