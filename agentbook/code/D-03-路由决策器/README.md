# D-03　路由决策器：规则／语义／级联三策略对比

对应书中：**第 4 章 4.5、4.7 节**。演示两件事：①三类路由策略在同一批任务上的成本-质量-延迟差异；
②"只路由第一跳约等于只优化一成半"——agent 一次用户轮次是多次模型调用，路由必须做到调用点级。

## 一句话

零依赖模拟一个三档模型池（small=1 / mid=3 / flagship=10 相对成本单位），在同一批任务上跑
规则路由、语义路由、级联升级三种策略，输出对比表并复现 4.5 的级联成本算式 `1 + u × 10`。
**它不测真实模型质量**——真实质量要用你自己的评估集测（第 18 章），本 demo 是"仪器"不是"结论"。

## 最低可跑组合

- **离线（推荐，书中所有数字都基于此）**：`--mock`。零依赖、零网络、零密钥。
- **真实调用**：本 demo 刻意不做真实调用——路由策略的对比结论必须在**固定评估集**上得出，
  接真实模型请先读第 18 章建好回归集，再把 `answer()` 换成经 `gateway.py` 的真实调用。
- **密钥处理方式**：不涉及密钥。若改造为真实调用，一律走环境变量（见 D-01 README）。

## 怎么跑

```bash
python router.py --mock                                    # 基线：200 任务、hard_ratio=0.3
python router.py --mock --tasks 500 --hard-ratio 0.6       # 改变难度分布，看 u 与成本如何联动
python router.py --mock --judge-recall 0.5                 # 判别器变弱：级联质量下滑、u 上升
python router.py --mock --first-hop-only                   # 复现 4.7 的"第一跳陷阱"实验
```

## 预期输出（`--mock`，2026-10-14 实测）

```
tasks=200｜hard_ratio=0.3｜judge_recall=0.8｜judge_fpr=0.1｜成本口径：small=1, flagship=10（相对单位）

全旗舰（基准）        10.00   99.0%   1500   0.00
全小模型（基准）       1.00   80.0%    200   0.00
规则：关键词命中即旗舰  3.48   98.0%    558   0.00
语义：相似度差          3.48   98.0%    558   0.00
级联：小→判别器→旗舰    3.80   93.0%    620   u=0.28

【4.5 算式核对】实测 u = 0.28；1 + u × 10 = 3.80 → 算式被复现
【4.7 实验】只路由第一跳（plan 占 15%）→ 节省 9.8%；路由全部调用点 → 节省 65.3%
```

## 观察什么

1. **级联成本随 u 线性上升**（`1 + u × 10`）：把 `--hard-ratio` 调大，u 与成本同步上升；u > 0.5 时不如用规则把难任务直接分给旗舰。
2. **语义路由的质量-成本点落在规则与全旗舰之间**：阈值决定它在前沿上的位置（图 4-3）。
3. **判别器质量决定级联的下限**：`--judge-recall 0.5` 会让该升的不升（质量掉）或不该升的都升（成本涨）——这就是 4.5 "级联的经济性取决于判别器"的实测形态。
4. **第一跳陷阱**：`--first-hop-only` 与全调用点对比，节省率 9.8% vs 65.3%，验证 4.7 的论断"只优化第一跳约等于只优化一成半"。
5. token 占比参数（`CALL_POINT_SHARES`）是智航案例的设定形状，不是任何真实系统的测量值；读者应替换为自己轨迹日志里的真实分布。

## 已知局限

- 语义相似度用字符二元组 Jaccard 式余弦近似，仅为演示路由决策的形状；生产须用真实嵌入模型＋低延迟向量库。
- 正确率是注入参数（`TierSpec.acc_easy/acc_hard`），不是模型实测；换真实模型前必须先有评估集。
