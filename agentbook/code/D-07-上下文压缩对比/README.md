D-07 上下文压缩对比（第 6 章配套 Demo）

## 演示什么

同一批 50 轮工单会话内容（mock 剧本、虚构数据），四种装配策略各自把**三本账**（书 6.3）付成什么形状：

| 账 | 仪器 | 对应章节 |
| --- | --- | --- |
| 成本账 | 累计输入 token（相对 none 的倍数） | 6.3.1 平方重放 |
| 质量账 | 承重字段探针（第 10/25/40 轮问订单号） | 6.3.2 有效注意力、6.4 细节蒸发 |
| 缓存账 | 每轮装配与前一轮的公共前缀复用率 | 6.3.3／6.8 缓存友好序列 |

## 快速开始（零依赖、无 API key）

```bash
python3 run.py --all                      # 四策略对照表＋短任务对照＋探针明细
python3 run.py --strategy tiered          # 单跑生产推荐形
python3 run.py --all --dump-composition   # 附第 40 轮七成分归账（表 6-1 仪器）
```

## 实测输出解读（截至本次提交）

```
策略        账单(相对)  探针通过率  前缀复用率
none         1.00x      100%       96%
truncate     0.45x        0%        8%
summary      0.30x      100%        1%
tiered       0.49x       67%       50%
```

四个必须看出的形状：
1. **none 是成本换质量的极端**——全量保留当然答得对，但账单 1.00x 是基准而非"可接受"；真实系统里这条曲线按平方走（书 6.3.1）。
2. **truncate 探针全灭**——承重信息（订单号）刻意放在第 1 轮，FIFO 截断专杀承重墙（书 6.4 策略一的"不知道什么重要"）。
3. **summary 靠钉住承重字段满分，但缓存复用归零**——每轮重写历史 = 每轮击穿前缀缓存（书 6.8 规范二；两卡张力的实测现场）。
4. **tiered 在第 10 轮探针失败**——远区尚未形成、中区摘要还没建立时的过渡窗口暴露给"细节蒸发"；这正是书 6.4"层间迁移要有日志"要防的边界时刻。短任务对照（前 10 轮）里 tiered 并不比 none 便宜多少——印证"≤10 轮别整理"。

## ⚠️ 免责与口径（QWEN.md 铁律三）

- 本 demo **不调用任何模型**：模拟的是装配层行为。摘要损失率、探针判定均为脚本化替身，只演示机制与相对形状，**不代表任何真实模型的压缩质量**。
- token 估算为块级近似，口径同 D-01 README：只看增长形状，不要对齐绝对数值。

## 接真模型

`run.py` 的策略函数接收轮列表、返回装配视图。接真实会话时：把 `make_script()` 换成你的会话日志重放器（每轮带真实 usage 计数），把 `probe()` 换成真模型问答 + 判分（评估方法见书 6.11 视角盒②与第 18 章）。三本账的记账逻辑不用动。
