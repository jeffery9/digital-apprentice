# D-05　规划模式对比：ReAct vs Plan-and-Execute

对应书中：**第 5 章 5.2／5.3／5.10.1**。演示两种规划形态在同一任务上的轨迹差异与各自的账。

## 一句话

在 D-01 的循环基座上加两样东西——显式计划工件（PE 路径）与前提失效触发器——用三个指标对齐比较：**模型调用次数、累计 token、无效步比例**（循环打转的量化）。

## 验证信息

| 项 | 值 |
| --- | --- |
| 验证日期 | 2026-10-14 |
| 验证环境 | Python 3.11+，Linux，**无网络、无 API key** |
| 验证方式 | `python planning.py --mock` 及下表全部变体，逐条核对输出 |
| 依赖 | 无第三方依赖（见 `requirements.txt`） |
| 随机种子 | 默认 `seed 20261014`，输出可复现 |

## 命令矩阵

| 命令 | 演示点 | 实测形状（mock） |
| --- | --- | --- |
| `--mock` | 两策略并跑对照 | react 5 次调用/3,847 tok vs pe 5 次/1,022 tok；PE 执行步输入≈恒定 |
| `--mock --perturb` | 同一事件两条轨迹分叉（5.10.1②） | pe 出现 `[replan]` 步，计划留痕 v1→v2，调用数 5→7 |
| `--mock --loop-spin --strategy react` | 循环打转＋检测器（5.2 失效一） | 无效步 2/8，token 涨至 13,718（平方账肉眼可见） |
| `--mock --dump-trace t.json` | 反模式一的离线复算数据源 | 落盘含 kind/action/invalid 字段 |

## ⚠️ 读数免责

mock 只演示**机制与相对形状**，不代表任何真实模型的规划质量（QWEN.md 铁律三）。
真实对比请用你的模型池与任务集重跑——5.13 最后一条延伸阅读就是这件事的操作说明。
注意本 demo 中 PE 的计划由规则生成（形状示范）；真实系统里那是规划调用点的模型输出。
