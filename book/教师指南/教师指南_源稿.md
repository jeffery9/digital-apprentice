# 《数字见习生》教师指南

> 适用对象：以本书开设通识课／选修课的教师、工作坊带教者、读书会主持人，以及需要给学生做示范的助教。与书内附录的分工：**附录 E**（教学使用建议）是给读者看的“课程大纲缩略版”，随书发行；**本指南**是给教师看的“授课操作手册”，是附录 E／F 的展开与落地，独立成册、不并入学生用书。阅读方式：可顺读，也可按“开课之前 → Markdown 入门 → 逐章授课 → 考核评分 → 活动与答疑”五部分按需取用。凡标 ★ 者为第一次开课的必修环节。编号约定：本指南小节以 **G-x** 编号；教师专用表单以 **【教师表单 TG-xx｜…】** 编号，与书内学生表单 T-01～T-12 分开，互不占用。语气红线与全书一致：不制造焦虑、不俯视说教、不做身份化吹捧。本指南默认读者是“愿意认真备课的老师”，不假设你有编程背景——**第二部分会从零基础讲清 Markdown**。

## 第一部分　开课之前（教师准备）

### G-1　本指南怎么用：三张地图

第一次拿到这本书要开课，你需要的不是一条命令，而是三张地图：**结构地图、能力地图、课时地图**。

**结构地图——这本书为什么“倒着教”。** 全书三段：先入门（第 1 章，30 分钟最小理论＋组装）→ 再动手（第 2–6 章，六个构件实验＋毕业项目）→ 然后深入（第 7–13 章，把理论当查阅手册）→ 最后清醒（第 14–15 章，边界、伦理与未来）。这与传统“先讲透原理再动手”的顺序相反。教师最容易犯的错，是把第二篇的原理章搬到第一篇之前“打好基础”——那会亲手拆掉本书的教学设计。**原理是动手之后按需查的手册，不是动手之前的门槛。**

**能力地图——你要教出的是三级能力。** 会组装（能按模板搭出一个能跑的数字见习生）→ 会判断（能说清每个构件为什么这么配、翻车归因到哪一条）→ 会设计（能为一个真实任务从零设计蓝图并测试）。毕业项目与展评答辩考的是第三级；六个实验考的是第一、二级。评分导向请见 G-15、G-16。

**课时地图——三种开课形态。** 32 课时完整版（附录 E §E-1）、16 课时精简版（附录 E §E-2）、无教师读书会版（附录 E §E-7）。本指南第三、四、五部分的教案按 32 课时展开，精简版与读书会版给出裁剪原则，不另写一套。

◆ **一句话记住本指南的定位**：附录 E 告诉你“教什么”，附录 F 告诉你“实验怎么做”，本指南告诉你“作为老师，第一周该准备什么、每一章站在讲台上说什么、学生交上来的东西怎么评”。

### G-2　开课前三件必修（教师本人先会）

1. **★ 读懂三段结构与翻转课堂的耦合。** 本书“课内动手与讨论、课外按需读理论”不是口号：第二篇原理章篇幅大、术语密，若课内逐字讲必然挤掉动手时间。翻转课堂是三段结构的天然授课形态——教师必须接受“理论章不在课内通讲”这件事（组织法见 G-13）。
2. **★ 会用 Markdown。** 本书全部可交付物——记录单、一页纸蓝图、员工手册、见习生工位、交接单——都是 Markdown 文本文件。你既要自己能读写，也要能在第一堂课用 40 分钟教会学生最小子集。**第二部分（G-5～G-10）就是为此准备的 Markdown 入门，教师请先自学一遍。**
3. **选定全班统一工作台（A 线或 B 线）。** A 线＝终端智能体（如 Qwen Code 一类命令行工具），B 线＝对话式 AI 自定义助理（网页/App 内配置）。二者对应本书贯穿案例的双轨。**建议全班统一一种**以减少环境排障负担，毕业项目允许自选。选择方法：用第 1 章表 1-2 的五标准当堂评估——评估过程本身就是一课（见 G-3、G-11）。

### G-3　环境与账号准备清单（开课前一周完成）

> 说明：本清单只列“需要教师提前确认的事项”，不含具体产品的注册步骤——产品界面与功能以附录 C 时效声明为准，随时可能改版。带 ☐ 者为逐项打钩项。

| 类别 | 待确认事项 | 兜底做法 |
|---|---|---|
| 设备 ☐ | 学生是否有可用终端（A 线）或浏览器/App（B 线）；机房能否安装或免安装运行 | 无设备者走“纸面替代版”（附录 F §F-1），验收标准不变 |
| 网络 ☐ | 校园网能否访问所选产品；是否有并发限制或流量墙 | 提前一天全班联通性测试；备离线推演方案 |
| 账号 ☐ | 是否需学生自行注册；有无教育版/团队版；费用与额度 | 明确额度上限，把“尺寸是预算”（第 8 章）当作第一课的成本教育 |
| 合规 ☐ | 校园产品的数据合规、未成年人/隐私政策由谁确认 | **教师先行确认**，不得让学生自行判断数据能否上传 |
| 脱敏 ☐ | 实验材料（值班表、名单、成绩）是否已化名脱敏 | 一律脱敏（第 1 章安全带第一条）；提供化名对照由教师保管 |
| 备份 ☐ | 学生成果（手册、记录单、蓝图）存在哪、如何收 | 统一提交格式见 TG-M2；建议纯文本/Markdown，避免只收截图 |

**安全带三条，开课前向全班宣读并张贴**（第 1 章 §1.4）：**脱敏、不外发、留痕**。凡涉及对外发送的动作（发邮件、发消息），本书一律要求“AI 只出草稿、由学生本人点击发送”——这条规矩第一次课就要立起来，不是等到第 14 章才讲。

### G-4　课程契约与学术诚信政策（第一周即发布）

**先立规矩，再教工具。** 本书第 14 章 §14.6 有“学术四底线”，但那是给读者的原则；教师需要把它翻译成**本课程的具体规定**并在第一周发放。一份可直接改写发布的政策模板见 G-23／TG-B，核心应回答四个问题：

1. **哪些环节允许用 AI**：本书的动手环节本就要求用 AI，这不是“作弊”而是“教学内容”；需要界定的是“记录与报告”环节允许 AI 协助到什么程度（附录 F §F-4 的 P-1～P-4 是官方允许的协助 Prompt）。
2. **如何披露**：凡用 AI 协助整理记录、起草报告的，必须在 T-12 第⑥段勾选并注明所用 Prompt 编号。**披露不是减分项，隐瞒才是**——请把这句话写进课程政策原文，并当堂宣读。
3. **哪些必须本人手写**：归因、设计反思、数据核验签字（T-12 第④段归因与第⑥段签名）。这是 F-5 的分工红线，也是本课程区分“会判断”与“只会搬运”的评分线。
4. **违规怎么处理**：发现一处编造（AI 生成的假数字/假引文进入报告未核验），按 F-5 核验红线“整份报告作废重做”。

◆ **给教师的提醒**：不要把 AI 使用政策写成一张“禁止清单”。本书的立场是“制度可以借 AI 的手，不能借 AI 的责任”——政策要教学生**如何负责任地借力**，而不是把工具污名化。一份全是“不许”的政策，会把这门课的第一印象变成“防守”，与全书语气红线相悖。

## 第二部分　Markdown 入门 ★（教师必修，可直接搬进第一堂课）

> 这一部分是写给“没写过一行代码”的老师的。读完你会明白：Markdown 不是编程，它是一种**带轻量排版记号的纯文本**；这本书之所以处处是 Markdown，是因为**配置一个数字见习生，本质上就是写几份结构清晰的文本**——员工手册、资料清单、操作手册、记录单。会 Markdown，就是会“把话说清楚并排好版”，仅此而已。结构：G-5 为什么这本书离不开它 → G-6 40 分钟最小子集（逐条：源码→效果→书中用途）→ G-7 语法到本书表单的映射 → G-8 学生最常犯的 8 个错 → G-9 一课时教案 → G-10 两张教师表单（速查卡＋提交格式约定）。

### G-5　为什么这本书离不开 Markdown（先破除“这是编程”的误解）

**Markdown 是什么，一句话**：一种用少量符号（`#`、`*`、`-`、`|`、`>`）在纯文本里标注“这里是标题、这里加粗、这里是表格”的写法。文件后缀通常是 `.md`。你用它写下的东西，人和机器都能直接读——不打开任何软件也是一份通顺的文本。

**它和编程的区别，讲给学生听就用这三句**：

1. 编程是**给计算机下指令让它算**；Markdown 是**给人和 AI 看的一份排版好的说明**。前者写错一个符号程序会崩，后者写错一个符号顶多“这一行没加粗”，不会有任何东西“坏掉”。
2. Markdown 没有“运行”“编译”“报错退出”这些概念。它永远只是文本。你随时可以删、可以改、可以复制进任何对话框。
3. 学 Markdown 需要记的符号，比学任何一门编程语言少一个数量级。**本书用到的子集，40 分钟能教会，一节课能练熟。**

**为什么 AI Agent 的世界处处是 Markdown**：本书第一篇的六个构件，落到磁盘上几乎都是 Markdown 文件——

- 构件一“员工手册”（第 2 章）＝一份分节的文本，用 `#` 分要素、用 `-` 列规矩；本书项目自己的员工手册就叫 `QWEN.md`。
- 构件二“资料室”（第 3 章）＝一堆说明文档，常用 Markdown 写索引与出处。
- 构件三“技能/Skill”（第 4 章）＝四段式操作手册，也是文本。
- 构件四“子代理交接单”（第 5 章）＝一张 Markdown 表格（T-07）。
- 构件五“工作流蓝图”（第 6 章）＝一页纸蓝图，Markdown 表格＋勾选框（T-10）。
- 全部实验记录单、报告模板（T-01～T-12）＝Markdown 表格。

换句话说：**学生学会了 Markdown，就学会了“用什么格式把配置和记录写下来交给 AI 和老师”。** 这不是额外技能，是完成本书全部动手任务的“书写姿势”。

◆ **概念桥（可直接板书）**：把 Markdown 想成“带记号的 Word”。Word 里你点工具栏按钮把一行字设成标题；Markdown 里你在这行字前面敲一个 `#`。按钮变成了符号，仅此而已。

### G-6　40 分钟最小子集：九个记号，够用一整门课

下面每一条都给三样东西：**源码怎么写**（放进代码框里，所见即所敲）、**效果是什么样**、**本书哪里用它**。教师照此顺序讲，学生照此顺序练。

**① 标题：用 `#` 分层，几个井号就是第几级**

```
# 一级标题（章/大节）
## 二级标题（小节）
### 三级标题（更细）
```

效果：字号从大到小、层级递进。`#` 与文字之间要有一个半角空格。书中用途：员工手册的“要素一～要素六”就是一级或二级标题；记录单的分区同理。**标题是 AI 读懂你手册结构的骨架。**

**② 加粗与斜体：星号包起来**

```
**加粗**用一个星号对，*斜体*用一个星号对。
```

效果：**加粗**、*斜体*。中文里优先用加粗，斜体在中文渲染下常不明显。书中用途：强调纪律、红线、验收关键词（如“**一次只改一处**”）。

**③ 无序列表：减号加空格**

```
- 第一条
- 第二条
  - 缩进两格变成子项
```

效果：项目符号列表；子项缩进两级空格。书中用途：手册里的“规矩”“边界”几乎都是无序列表。**减号后必须有一个空格**，否则会被当成普通文字。

**④ 有序列表：数字加点加空格**

```
1. 第一步
2. 第二步
3. 第三步
```

效果：带编号的步骤。书中用途：工作流程、五段流程、操作步骤。注意：Markdown 会自动重新编号，你写 `1. 1. 1.` 也会渲染成 1、2、3——**不必手工对齐序号**。

**⑤ 表格：竖线分列，第二行是分隔线**

```

| 列标题一 | 列标题二 |
|---|---|
| 单元格 | 单元格 |
```

效果：一张带表头的表格。第二行 `|---|---|` 是**分隔线，必须有**，它告诉渲染器“上面是表头”。冒号可控制对齐：`:---` 左对齐、`:---:` 居中、`---:` 右对齐。书中用途：所有记录单、蓝图、速查表、交接单。**这是本书用得最多的记号，也是学生最容易写错的地方**（见 G-8）。

**⑥ 引用块：大于号开头**

```
> 这是一段引用，常用于模板、原话摘录、旁注。
> 换行继续引用，每行都要有 >。
```

效果：左侧带竖线、通常缩进变灰的一段。书中用途：手册/技能/交接单/蓝图的**模板正文**在书里全部用引用块排版（见附录体例）；实验里抄录“AI 的原话”也用引用块，一眼区分“这是我写的”还是“这是 AI 说的”。

**⑦ 链接与图片：方括号配圆括号**

```
[显示文字](https://example.com)
![图片说明](图片文件路径.png)
```

效果：可点击的链接；图片（比链接多一个开头的 `!`）。书中用途：资料室文档里标注出处链接；插图引用。**方括号里是“给人看的文字”，圆括号里是“地址”**，顺序不能反。

**⑧ 任务清单/勾选框：减号空格方括号空格**

```
- [ ] 待办（未勾选）
- [x] 已完成（勾选）
```

效果：一个可打钩的方框 ☐／☑。注意 `[`  `]` 中间：未勾选是一个空格，已勾选是小写 `x`。书中用途：验收清单、核验清单、蓝图自检项。本书表单里的 ☐ 就是它的“印刷版”。**这是学生做验收打钩时的标准写法。**

**⑨ 分隔线与代码框：三个符号收尾**

```
---
```

效果：一条水平分隔线（注意：`---` 单独成行、前后各空一行才是分隔线；紧贴文字可能被误认）。

代码框用三个反引号把一段“原样文本”框起来（就像本指南里所有示例那样）：

````
```
这里面的东西原样显示，不会被当成记号
```
````

书中用途：分隔线用来分大节；代码框用来“展示一段不该被渲染的原文”——**当你要把一份 Markdown 源码当例子给学生看时，就用代码框把它包起来**，否则它会被渲染掉。本书坚持零代码，代码框在这里只用来“原样展示文本样例”，不是写程序。

◆ **比喻的边界（讲给学生，防止过度联想）**：Markdown 的记号只在“渲染时”起作用；在 AI 眼里，它读到的就是你敲的那些符号本身。所以**给 AI 的手册里用不用 Markdown，AI 都读得懂**——用 Markdown 主要是为了**人**（你、老师、队友）读起来结构清晰。别把“排版漂亮”误当成“AI 会更聪明”。

### G-7　把语法映射到本书表单（教师示范的黄金对照表）

学生记不住九个记号，但记得住“我要交的这张表长什么样”。把语法直接对到本书表单，是最有效的教法。下表可直接投影：

| 本书产物 | 主要用到的记号 | 对应表单/文件 | 一句话示范 |
|---|---|---|---|
| 员工手册 | 标题 `#`＋无序列表 `-`＋加粗 `**` | `QWEN.md`、第 2 章六要素模板 | 六个 `##` 标题就是六个要素，每条规矩一个 `-` |
| 资料室索引 | 标题＋链接 `[文字](地址)` | 第 3 章资料室、附录 C | 每份资料一行，出处用链接标注 |
| 技能卡 | 标题＋有序列表 `1.`＋引用块 `>` | 第 4 章四段式、`见习生工位/技能/` | 四段各一个 `##`，模板正文放引用块 |
| 交接单 | 表格 `\|` | T-07 | 单据要素做成表格字段行 |
| 一页纸蓝图 | 表格＋勾选框 `- [ ]` | T-10 | 五要素做表，自检项用勾选框 |
| 实验记录/报告 | 表格＋引用块＋勾选框 | T-01～T-12 | 结果汇总用表，AI 原话用引用块，披露用勾选框 |

**课堂示范脚本（5 分钟，教师当场敲）**：新建一个 `手册.md`，边说边敲出下面这份“最小员工手册”，让学生看到“一份能交给 AI 的手册，其实就这么点符号”：

```
# 课程秘书·员工手册

## 角色
你是课程秘书，服务对象是本周值日的同学。

## 规矩
- 先问清日期和任务，再动手
- 涉及对外发送，只出草稿，由我本人点击发送
- **一次只改一处**，改完复测

## 输出格式
- 待办清单用表格：任务、截止、负责人
```

敲完把这段贴进工作台，让 AI 按手册办事——学生会立刻明白“原来配置 AI 就是写这么一份文本”。**这一步是全书最重要的‘去神秘化’时刻，务必当堂做，不要只用幻灯片。**

### G-8　学生最常犯的 8 个 Markdown 错误（附排查口诀）

提前把这 8 个坑写在黑板一角，能省掉半个学期的答疑时间。每个都给“症状→原因→改法”：

1. **表格不显示、竖线原样出现**。原因：表头下面漏了分隔线 `|---|---|`，或表格紧贴上一行文字没空行。改法：补分隔线；表格前后各留一个空行。（本书构建脚本专门有 `ensure_table_blank_lines` 兜底这个坑，但学生手写时仍需自己注意。）
2. **列表没变成项目符号，减号原样出现**。原因：`-` 后面漏了空格，写成 `-第一条`。改法：`- 第一条`。
3. **勾选框显示成 `[ ]` 文字而非方框**。原因：写成 `-[ ]`（缺空格）或 `-[x]`。改法：`- [ ]`、`- [x]`，减号后、方括号内都要空格。
4. **中英标点混用导致表格错位**。原因：用全角竖线 `｜` 当分隔符，或全角空格缩进。改法：表格分隔一律用半角 `|`；缩进用半角空格。（注意：本书表单标题里的 `｜` 是**标题文字**的一部分，不是表格分隔符，别混。）
5. **标题不生效，`#` 原样出现**。原因：`#` 后漏空格，或 `#` 前没空行紧贴上一段。改法：`# 标题`，且标题行前空一行。
6. **加粗只出现一半**。原因：星号数量不对称，如 `**加粗*`。改法：成对，`**加粗**`。
7. **链接点开是错的/图片裂开**。原因：方括号与圆括号顺序反了，或图片路径不对、少了开头的 `!`。改法：`[文字](地址)`、`![说明](路径)`。
8. **分隔线变成了标题**。原因：`---` 紧贴在一行文字正下方，被当成“把上一行设为标题”的语法。改法：`---` 前后各空一行。

◆ **排查口诀（让学生背下来）**：**“行前空一行、符号后空一格、表格要有分隔线、勾号方框别忘空格。”** 90% 的 Markdown 显示问题都能用这四句自查解决。

### G-9　Markdown 一课时教案（40–45 分钟，可插在第 1 章导论课后）

| 时段 | 环节 | 教师动作 | 学生产出 |
|---|---|---|---|
| 0–5 分 | 去神秘化 | 板书“Markdown＝带记号的 Word，不是编程”；展示 `QWEN.md` 真实文件 | 破除“这是代码”的恐惧 |
| 5–20 分 | 九记号速讲 | 按 G-6 顺序，每讲一个记号当场敲一遍、渲染给学生看 | 跟练笔记 |

### G-11　导论课教案（第 1 课时）

**目标**：让学生当堂跑通“30 分钟入门＋组装第一个数字见习生”，并立起课程契约与安全带。

**流程**： 1. 讲三段结构与课程契约（10 分钟）——用 G-1 的三张地图；当堂发放并宣读 G-4 的 AI 使用政策。 2. Markdown 速成（若未单独设课时，可压缩到 15 分钟，只讲 G-6 的①③⑤⑧四个记号）。 3. 当堂完成第 1 章实验 1（30 分钟入门＋组装课程秘书，表单 T-01）。 4. 收束：宣读安全带三条，布置“把 T-01 记录单以 Markdown 提交”。

**教师示范脚本要点**：现场用第 1 章表 1-2 的五标准评估、选定全班统一工作台——**把选择过程讲出来**（为什么选 A 不选 B），这本身就是“会判断”的第一课。

**给教师的坑**：不要在导论课讲第二篇的原理（上下文窗口、RAG 等）。学生此刻只需要“能组装、能记录”，原理留到动手之后按需查。**过早灌输原理＝亲手拆掉三段结构。**

**第一篇每章 2 课时的固定节奏**（附录 E §E-1）： - 第 1 课时：翻车复盘（10 分）→ 构件讲解（20 分）→ 教师示范（15 分）。**复盘一定用上一实验的真实翻车记录，不从零讲概念。** - 第 2 课时：实验工坊（30 分）→ 三人互评（10 分）→ 提交记录单（5 分）。互评用该章验收标准逐项打钩。

**给教师的三个坑（第一篇通用）**： 1. **别替学生改手册**。学生手册写得烂，正是教学素材——让他自己撞一次“AI 自由发挥”的车，再引导归因。你替他改好，他就永远学不会“手册是安全带，不是保险柜”。 2. **A/B 对比不能省**。第 2 章的核心学习发生在“新旧两版手册对比”的那一刻；只交新版、不做对比的，等于没做实验。 3. **验收要指到具体一行**。学生说“过了”，追问“指到记录单哪一行”——这是把“感觉差不多”逼成“可核验”的关键动作，也是全书“AI 输出是待核验的初稿”的课堂落地。

### G-13　第二篇原理章怎么讲（第 7–13 章，查阅式而非通讲）

**核心原则**：第二篇是“需要时再懂的原理手册”，**不在课内逐字通讲**。32 课时方案里：精讲 4 章（第 8、9、12、13 章各 2 课时）＋学生主讲 3 章（第 7、10、11 章各 1 课时）＋研讨 1 课时（附录 E §E-1）。

**现象索引导入法（精讲章通用教案）**： 1. 从一个“第一篇动手时见过的现象”切入（如“为什么 AI 有时记不住前面说的话”→第 8 章上下文窗口）。 2. 用该章章首“现象索引”把现象与原理挂钩，只讲学生动手时真正困惑的那几条。 3. 延伸阅读（章末）作为“想深挖的人课外读”的指引，课内不展开。 4. 落回动手：这个原理解释了你实验里的哪次翻车？

**学生主讲组织法**：小组按“现象索引”认领一章，备课任务不是“讲全”，而是“挑三个现象、各配一个自己动手时的例子，讲清楚原理如何解释现象”。教师用附录 B 检索总表核对主讲组是否漏掉关键现象。**主讲是加分项（附录 E §E-3），但认领后须真讲——防止挂名。**

**给教师的坑**：不要因为在座有计算机专业学生就临时加深原理难度。本书的读者假设是“无编程经验”，原理章的深度以“能解释动手现象”为限，**不为少数人拔高，那会把多数学生甩下车**（违反语气红线：不俯视、不制造焦虑）。

### G-14　第三篇讨论课与展评（第 14–15 章＋展评，不讲授）

**第 14 章（守住边界）2 课时＝案例讨论课**：用第 14 章的越狱 vs 注入案例、学术四底线，组织讨论而非讲授。可把“署名临界点”“无 AI 体检制度”等开放题（附录 E §E-5）合并成一次课程辩论。

**第 15 章（展望）2 课时＝圆桌与课程收束**：讲“三错觉”“三动作”，回到全书金句“AI 答‘怎么做’，人问‘为什么’”，让学生谈自己一学期的位置变化。

**展评 2 课时**：每人/每组 5 分钟演示＋3 分钟答辩；答辩必考“蓝图三问”（附录 E §E-4，主持脚本见 G-17）。

**16 课时精简版裁剪原则**（附录 E §E-2）：导论 1＋第一篇 8（第 2–6 章各 1.5 课时，毕业项目并入课外）＋第二篇精讲 2（只讲第 8、12 章）＋第三篇 2＋展评 2＋机动 1。**精简铁律：动手不砍、理论选讲、讨论保留。**

## 第四部分　考核与评分实操

> 附录 E §E-3 给了权重骨架（实验记录 40%＋毕业项目 60%＋加分 ≤5%）。本部分把它展开成可操作的评分细则（rubric），并解决教师最头疼的两件事：**怎么给“诚实的失败”高分**、**怎么识别 AI 代写与抄袭记录**。

### G-15　评分细则展开（rubric）

**A. 六个实验记录（40%）**：实验 1 占 4%，实验 2–5 各占 7%，实验 6/测试方法占 8%。每个实验按四档评分，档位描述如下（以“翻车归因质量”为核心轴，而非“产出漂亮程度”）：

| 档位 | 记录完整性 | 归因质量 | 验收可指认 | 得分区间 |
|---|---|---|---|---|
| 优 | 惊喜/翻车均有原话留证 | 归因指到具体构件＋具体条款，且复测通过 | 每个“过”都能指到记录单某一行 | 90–100% |
| 良 | 有留证但个别缺原话 | 归因到构件层，未到条款 | 多数可指认 | 75–89% |
| 中 | 只写“翻车了”无证据 | 归因含糊（如“AI 笨”） | 靠“感觉差不多” | 60–74% |
| 差 | 记录缺失/事后补造 | 无归因或归因错误 | 无法指认 | <60% |

**B. 毕业项目（60%）**：一页纸蓝图 15%＋系统演示 20%＋十例测试报告 15%＋500 字设计反思 10%。逐项要点： - **蓝图（15%）**：五要素齐全、自由度光谱位置有依据（凭三问中哪一问定的）。缺项或光谱位置说不出依据，扣分。 - **系统演示（20%）**：能跑通、能当场复现一个测试用例；演示“翻车后如何救回”比“一路顺风”更能得分。 - **十例测试报告（15%）**：十例含至少三例“刁难”用例；每例判定只看可观察行为；“过程观察”栏（绕路/跳自检/碰禁止材料）必填。缺刁难用例或过程观察空白，重扣。 - **设计反思（10%）**：500 字，必须本人手写归因与判断（T-12 第④段归因、第⑥段签名）。AI 起草但披露且本人核验的，不扣分；未披露的按隐瞒处理。

### G-16　“奖励诚实的失败”如何落地评分

本课程最反直觉、也最重要的一条评分导向（附录 E §E-3，请向学生宣读原文）：**本课程不考核“AI 产出多漂亮”，考核“设计决策能否说清”。测试全过但说不清归因的，低于翻车两次但归因清晰的。**

**两份样例，投影给学生对照**：

> **样例甲（高分·诚实的失败）**：实验 3 记录单写着“库外题第 4 问，AI 编了一个不存在的出处《××研究 2023》”，引用了 AI 原话两句；归因栏写“资料室索引缺‘无答案时的兜底条款’，手册第三节只说‘用资料回答’没说‘没有就说没有’”；修改栏写“在手册加一条‘库内查无，明确回复没有并停止’”，复测通过。——**这份得优。** 它翻车了，但归因到条款、改了、复测了。
>
> **样例乙（低分·漂亮的空壳）**：实验 3 记录单写着“十问全部通过，助理表现很好，回答准确专业”。无原话、无过程观察、归因栏空白。——**这份得中或差。** 它“全过”，但没有证据、没有归因，无法判断是真过还是挑了简单题。

**给教师的坑**：不要下意识给“看起来成功”的记录高分。你的评分信号会被学生反向学习——**你奖励什么，学生就生产什么。** 若你奖励漂亮产出，学生就会藏起翻车；若你奖励诚实归因，学生才敢把最丑的翻车摆上台面，而那正是学习真正发生的地方（第 10 章“反思要有外部信号”）。

### G-17　展评答辩主持脚本与“蓝图三问”追问树

**主持流程**：每人/组 5 分钟演示＋3 分钟答辩。演示计时严格，超时打断。答辩必问“蓝图三问”（附录 E §E-4），并备好追问树：

1. **问**：你的系统在自由度光谱上的位置是哪？凭三问中哪一问定的？
   - 追问：如果把这个任务换成“自动发送邮件给全班”，光谱位置要不要动？为什么？
2. **问**：十例测试里最难看的一次翻车，归因到哪个构件、哪条制度？
   - 追问：那次翻车之后你改了什么？复测了吗？（若答不出复测→归因未闭环，扣分）
3. **问**：如果重做，你会改动蓝图五要素中的哪一项？为什么？
   - 追问：这个改动会不会引入新的翻车？你怎么提前测到它？

**答辩评分**：三问各占答辩分的一部分；“能指到记录单/测试报告某一行”的得高分，泛泛而谈的得低分。**答辩考的不是系统多强，是设计者能否为自己的决策辩护。**

### G-18　防抄袭与识别 AI 代写的核查动作

本课程鼓励用 AI，但要求“分工红线”（F-5）：AI 可整理、排版、汇总、提问；不可替做归因、反思、核验签字。核查动作：

1. **要原话证据**：记录里引用的 AI 原话，随机抽一条让学生当场在工作台复现或指出会话位置。造不出来的，记录存疑。
2. **查过程观察栏**：AI 代写的报告往往“结果漂亮、过程空白”。凡“过程观察”栏一律写“无异常”的十例报告，重点核查——真实的测试不可能十例全无绕路。
3. **问归因链**：口头追问“这次翻车→归因到哪条→改了什么→复测结果”，四环缺一即追问。AI 代写者通常答不出“改了什么”和“复测结果”这两环（因为那不是他做的）。
4. **看披露**：T-12 第⑥段披露栏空白但报告文风明显 AI 化的，按“隐瞒”处理；主动披露且能本人核验的，正常给分。**披露是加分信号，不是嫌疑信号。**

◆ **给教师的边界提醒**：不要把“疑似 AI 代写”直接等同作弊处理。本书立场是教学生**负责任地借力**——第一步永远是“请他把归因和核验当场讲一遍”，讲得出就是真会，讲不出再按课程政策处理。

### G-19　讨论题与辩论题清单（按篇取用）

**思考题三类分工**（附录 E §E-5）：复述题作课前自查（不计分、抽查）；辨析题作课内小组讨论（10 分钟、随机抽组陈述）；开放题作小论文（400–600 字）或辩论选题。

**现象索引主讲怎么评**（第二篇）：主讲组须“挑三个现象、各配一个自己动手的例子”；教师用附录 B 检索总表核对是否漏掉关键现象；听众用一句话反馈“这个原理解释了我哪次翻车”。

**模拟面试（v1.0.2 新增，配附录 G）**：展评周或就业指导课用。学生两两互考附录 G“面试十五问”：答题者用一句答案骨架＋自己的证据锚点作答（锚点必须来自本人六实验与毕业项目，即 T-11 台账）；提问者按“三忌”挑刺——背数字者判负、说“AI 不会犯这个错”者要求改口为“这个错我们有核验兜着”、用术语挡追问者要求回到比喻重讲。每人记下自己最弱的一问，回附录 G 复读对应词条。
### G-20　教师常见排障 FAQ

**Q1：学生没有设备/网络，怎么办？** A：走“纸面替代版”（附录 F §F-1）——用纸面填一页纸蓝图（T-10），用本章记录单推演“AI 可能怎么答、哪些算翻车”，附一段真实产品对话截图佐证。**验收标准不变：归因与推演都要能指到具体条款。** 这保证无设备条件下仍可完成考核（附录 E §E-6 第 5 条）。

**Q2：产品课堂上突然改版、界面变了，怎么救场？** A：把“变化了什么、构件逻辑变没变”当作即兴讨论题。这正是“跟踪原理层、忽略产品层”（第 15 章 §15.4）的现场教学——产品层天天变，构件逻辑（手册/资料/技能/子代理/工作流）稳定。以附录 C 时效声明为准。

**Q3：学生的 AI 明显在编造（幻觉），课堂怎么处理？** A：这是**教学机会不是事故**。让学生把编造的原话抄进记录单，归因到“资料室缺出处/手册缺兜底条款”，用第 3 章核验清单四问核验。把“AI 输出是待核验的初稿”从口号变成一次亲手抓幻觉的经历。

**Q4：课时不够，动手和理论砍哪个？** A：**砍理论，不砍动手**（附录 E §E-2 精简铁律）。理论章本就是“按需查的手册”，可让学生课外自学＋课内主讲；动手是能力形成的唯一途径，不能砍。

**Q5：学生只让 AI 出漂亮结果、不肯记录翻车，怎么破？** A：调整你的评分信号（G-16）。当学生发现“翻车两次但归因清晰”得分高于“测试全过但说不清”，他们就会主动记录翻车。**问题通常不在学生，在评分导向。**

**Q6：有学生互相抄袭记录单，怎么办？** A：用 G-18 的核查动作——要求当场复现引用的 AI 原话、追问归因链四环（翻车→归因→改了什么→复测）。抄来的记录答不出后两环。同时强调：本课程奖励诚实的失败，抄一份“漂亮记录”反而更容易露馅。

**Q7：院系或家长质疑“这门课就是教学生用 AI 作弊”，怎么回应？** A：出示课程 AI 使用政策（TG-B）与学术四底线（第 14 章 §14.6）——本课程恰恰是**教学生负责任地、可披露地、可核验地使用 AI**，并把“归因、反思、核验签字”划为必须本人完成的红线。这门课教的是判断力与制度设计，不是代写。

### G-22　与专业课协同、读书会与自学者

**与专业课协同**（附录 E §E-6 第 6 条）：鼓励学生把毕业项目选在自己专业的真实任务上（科研配方见附录 C），并邀请专业课教师参与展评。通识课与专业课的接口，正是“会组装→会判断→会设计”的第三级。

**读书会/自学者**（附录 E §E-7）：无教师场景下，三人成组，各自完成实验后互评（用各章验收标准）；第二篇按“每人认领一章、给另两人讲现象索引”轮讲；毕业项目互为答辩人，必问“蓝图三问”。本书互评工具（记录单、验收标准、检索总表）已按“无教师可用”设计——**本指南的 G-15～G-18 评分逻辑，读书会可直接搬来互评。**
