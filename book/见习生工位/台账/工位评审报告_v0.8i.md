## 一、总评

**结论：结构合格、可上岗；“自述一致性”需修一轮。**

- 骨架保真度高：六要素、四段式、三件套、节点表、T-07、T-10 逐项对过书内原文，字段一个不缺；全工位约 19 处章节引用，**节号无一错引**。
- 数字事实全部核实通过：版本 v0.8i 四处一致；199,715 字符、61 图、95 表、12 表单、47 项检查、T-01～T-12 口径、所引文件路径——与仓库现状逐项相符。
- 问题集中在两类，且都栽在这本书自己立的纪律上：
  1. **“带编号的名目”凭记忆转述失真**（三个升级信号、三样刹车、选择五标准）——这正是第 3 章 §3.3“引用核验清单”要防的病；
  2. **自述与现实脱节**（47 项检查脚本不在任何规范文件里、审计助理建卡后从未按卡启用、承诺归档的单据不齐、蓝图署名“作者审定”尚未发生）——这正是 T-07“遗留问题防装懂”要防的病。
- 修复量小：约 7 个文件、15 处上下，一轮闭环线可收口；其中两处属书稿侧（进度文件），需重跑组装与终检。

**值得点名的好设计**（建议保留并在 C-4 后续修订时可提及）：
- 审计助理与秘书终检“故意分权”（运动员自检 vs 质检员抽检），是第 10 章“反思要有外部信号”在自己项目上的正确安装；
- 交接单“禁止内容”栏把金句与【方括号】的**处置权**明确划归作者——红线升格为分工权限，比“注意金句”式软规矩可判断；
- 资料室选料单“不放什么”四条各带理由，尤其“把再生品放进库＝让见习生拿旧账本当事实”，达到可入书水准。

## 四、问题清单

### A 级｜事实错误与悬空引用（须修）

- **A1　README §三.1“三个升级信号”括注错**。现文“（调试账没爆、任务没有天然并行、上下文没撑破）”系把“三笔账”术语误当信号。书原文（第 5 章“扩编之前”）三信号为：①某类任务持续占用主协调超过三分之一轮次；②交接单某一栏反复出现同类遗留问题；③B 线人肉路由时间超过系统设计时间。“一个都没出现、不扩编”的结论仍成立，论据须换成真三信号。→ 改 `见习生工位/README.md`。
- **A2　“三样刹车”名目错，两处**。书原文（§6.2）三样刹车＝①停止条件②求助点③禁止清单。README §三.3 与改稿闭环线头部均写成“返工上限、步数时长上限、人工审核点”——把停止条件拆成两条、丢了禁止清单。蓝图⑤本身是对的（停止／求助点／禁止三条齐全），改齐两处转述即恢复三处一致。→ 改 `README.md`＋`工作流/改稿闭环线.md`。
- **A3　进度文件 §五 悬空引用**。四轮审校行指向台账《出版前检查报告_v0.8h》——该中间版已删除（开发日志第 4 行自证），D3a 内容现存于 v0.8i 报告。→ 改 `书稿/00_书稿进度.md`（书稿侧，走闭环线，需重跑组装＋终检）。
- **A4　进度文件 §六.1 完成项过期**。产物路径写“book/output/”（实际为 `输出/`）；“约 19.1 万字符、静态目录 185 条、表格 86 张、附录 A–E”均非现状（现 199,715 字符、目录 193 条、表 95、附录 A–F）。→ 同上文件；更新为现状，或明确标注为“当时快照”。

### B 级｜自述与现实脱节（建议修）

- **B1　`prepub_check.py` 在工位规范文件中零提及**。QWEN.md、三张技能卡、两份角色卡、闭环线、README 均未出现（只存在于台账叙事）。“第一天报到的新秘书”按手册工作将不知道项目最强检查工具的存在；审计助理卡说“独立重跑四类检查”却未指明用什么跑；依赖引导（`pip install pypandoc-binary python-docx pillow`，环境重置后须重装）只藏在进度文件 §六。→ 建议：「四类终检」技能加【工具】行（脚本优先、报告自动落盘台账、手工清单用于归因与增量复核）；审计助理卡④工作流程、闭环线◇自检节点、README §二各补半句。
- **B2　审计助理从未按卡启用，且交接单“填写示例”来历不明**。角色卡写明“每轮版本收口……由维护秘书分派”，但 v0.8h、v0.8i 两次收口均只有秘书自检＋脚本，台账无审计抽检、无任何交接单归档；而 `交接单模板.md` 的填写示例声称“v0.8g 终检复核……另发现附录 C 引言与 C-4 编号衔接一处存疑”——开发日志无对应记录。按本书纪律（不把占位当事实），二选一：标注“示例（非实录）”，或真跑一轮归档真单。**最优解**：本轮 A/B 级修复收口后（v0.8j），真派一次审计助理对修复批次抽检，归档首份真交接单并替换示例——同时闭合 B2 与 B3。
- **B3　闭环线“输出”行承诺与归档实践不符**。“构建报告＋终检报告＋交接单归档 台账/”——实际台账只有出版前检查报告一件（构建报告并入日志行、交接单零份）。→ 与 B2 一并处理：要么补齐归档，要么把条款改为与实际一致（构建报告要点并入日志行）。
- **B4　蓝图署名“（作者审定）”尚未发生**。本次评审是蓝图第一次接受作者正式审查。→ 若作者认可本轮评审结论，在开发日志补记“蓝图经作者审定”后保留；否则先改为“（待作者审定）”。
