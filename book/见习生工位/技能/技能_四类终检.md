# 技能：四类终检（四段式，第 4 章 §4.2）

> 安放位置：A 线——本文件即操作手册原件。检查对象是**合并版产物**，不是源稿；发现问题的修复回到源稿做，改完重跑「组装书稿」再终检——闭环不抄近路。

【工具】全书体检工具优先：`python3 prepub_check.py`（A–G 七组 47 项；对源稿只读；报告自动归档 `台账/出版前检查报告_vX.md`）。依赖：`pip install pypandoc-binary python-docx pillow`（沙箱环境随会话重置，先装再用）。下列手工四类清单的用途有三：对脚本 WARN／FAIL 项归因、增量小改的复核、脚本不可用时的兜底抽查。节奏：每轮版本收口必跑；送印前用 `python3 assemble_book.py --final` 构建后必再跑一次（重点复核 F2「排版说明」残留＝0）——「出版前检查线」即以此工具段并入本卡，暂不单立工作流（步骤少，卡内可容）。

【触发】出现以下任一情况时使用：①「组装书稿」完成之后（强制串联）；②作者要求“终检”“体检”“查一遍断链/引号/金句”；③任何登记表（表格成品集、插画交付清单）改动之后。与闲聊、单点问答、纯工位维护不使用。

【步骤】
1. **断链检查（双向）**：合并版中每处图片引用的文件必须存在；每个交叉引用（“见 §x.y／附录 X 第 n 条／图 x-y／表 x-y／T-xx”）的目标必须存在；反向——两张登记表里登记的每一件，正文必须实际引用（“登记有、正文无”同样是断链）；图片文件名批次前缀（P0_/P1_/P2_）逐个核对，前缀误引是高发错误；图号、表号、T 编号连续无跳号无重号；
2. **编号完整性**：每个表题行下方必须跟真实表体（有题无体＝事故）；每张 T-xx 表单四件套齐全（编号标题、表头字段行、示例行、脚注）；勾选框符号计数合理；
3. **引号与金句**：合并版 ASCII 直引号残留＝0；十句金句锚点（照录于进度文件 §四）逐句 grep 全书，措辞逐字一致；术语写法抽查高频 20 条与附录 A 术语表一致；
4. **表格构造**：docx 侧正文段落残留管道符＝0；docx 表格总数 ≥ 源稿管道表计数；markdown 侧所有管道表前后有空行；
5. 汇总成终检报告交付；任何一项不绿，报告里写明“不绿在哪、疑似原因、建议改哪个源文件”，**不自行修改被检内容**（修复是改稿任务，走闭环线）。

【模板】终检报告固定四行：
> 终检结果：①断链＝N 处（正向 N／反向 N／前缀 N）　②编号＝通过/不通过（缺项列出）
> ③直引号＝N／金句命中＝10 句各 N 处、逐字一致 ☑/☐　④表格＝残留管道符 N、docx 表 N 张
> 结论：全绿 ☐／不绿 ☐（不绿项＋疑似原因＋建议改动的源文件）
> 遗留问题：＿＿＿（没有也写“无”）

【自检】交付前自查：
①每一类都**实际跑过**检查命令或脚本，而不是凭上一轮结果打勾？
②金句是逐字比对，不是“大意一致”？
③不绿项都给出了可执行的修复指向（具体到文件与小节）？
