# 见习生工位：本书自己的数字见习生（总说明）

> “吃自己的狗食”——本书教读者组装数字见习生，本书自己的书稿维护也用同一套方法。
> 本目录就是按本书第一篇模板搭出的**真工位**：每个构件都注明模板出处，可逐一翻回书内对照。
> 书内导览见附录 C-4；本工位文件随书稿交付，学员做毕业项目（第 6 章 §6.5）时可当参照间。

| 构件（书中比喻） | 模板出处 | 本工位对应物 |
|---|---|---|
| 员工手册（Prompt） | 第 2 章 §2.2 六要素 | `book/QWEN.md`（项目根目录，A 线工作台自动加载） |

## 二、怎么用（A 线）

1. 用 Qwen Code 一类终端智能体打开 `book/` 目录——根目录的 `QWEN.md` 会被自动当作员工手册加载；
2. 开口即可派活，例如：“按工位规则改稿：把附录 C 时效声明的措辞统一为‘以编写截止日为准’”；
3. 见习生会走「改稿闭环线」：复述确认 → 读进度文件 → 一次改一处 → 组装 → 终检（工具优先：`python3 prepub_check.py`，A–G 七组 47 项，对源稿只读，报告自动归档 `台账/`）→ 报告；
4. 人工审核点在“采纳”：作者对照改前改后与终检数字拍板，版本历史才登记。

B 线（对话 AI 自定义助理）不适合维护 20 万字符的文件型项目——按第 1 章表 1-2“选择五标准”逐项打分即知输在哪：①能写员工手册，勉强得分（自定义指令）；②能挂知识库，不得分——20 万字符书稿无法整体上传供引用，更不能直读工作目录，一票否决；③④文件型技能与 Sub-agent／工作流的形态带不过去；⑤数据与合规需另查产品条款。本书维护需要**能读工作目录、能挂规则文件**的终端智能体。

## 三、工位自己守的三条纪律

1. **Sub-agent 只有两名。**第 5 章“扩编之前：三个升级信号”逐一核对：没有某类任务持续占用维护秘书超过三分之一的轮次；交接单没有哪一栏反复出现同类遗留问题；本项目不用 B 线人肉路由，更谈不上路由时间超过系统设计时间——一个都没出现，所以不扩编。按需爬楼（§6.6：级别不是勋章，是成本）。
2. **技能只有三张，一卡一事。**粒度纪律（§4.2）：没有“万能维护技能”；要用“和”字介绍的技能一律拆开。
3. **工作流带三样刹车（§6.2 下班制度）。**停止条件——单任务返工 ≤2 轮、全程 ≤20 步或 30 分钟；求助点——金句锚点、【方括号】占位、语气红线、对外发送、进度文件与书稿矛盾，一律停下问作者；禁止清单——见蓝图⑤与员工手册规矩 5 的各条“绝不”。这条线没有对外动作，审核点设在“采纳”；若将来加入“发送印厂”，闸口必须前移到发送之前。

## 五、给学员的话

这套工位不是标准答案，是**参照间**：它证明五类构件在一个真实的、20 万字符量级的项目里如何各就各位。你搭毕业项目时，建议照这个顺序抄作业——先写一页纸蓝图，再写手册，再配资料室，然后才轮到技能与分工；每一步都回书里翻对应章节的“翻车图鉴”对一遍。
