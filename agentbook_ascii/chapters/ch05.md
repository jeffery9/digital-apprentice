# 第5章 工具调用与 MCP 生态

## 5.1 Function Calling：Agent 的手脚

工具调用的流程：开发者以 JSON Schema 声明工具 → 模型在推理时输出结构化的调用请求 → 运行时执行并把结果回灌给模型。

```json
{
  "name": "search_web",
  "description": "检索互联网获取最新信息，返回标题、链接与摘要列表",
  "parameters": {
    "type": "object",
    "properties": {
      "query": { "type": "string", "description": "检索关键词" },
      "top_k": { "type": "integer", "default": 5 }
    },
    "required": ["query"]
  }
}
```

写好工具的三条经验：

- **描述即提示**：`description` 要写清何时用、何时不用，这是模型选工具的唯一依据。
- **窄接口**：一个工具做一件事；参数枚举化、少用自由文本。
- **错误也是返回值**：把失败原因结构化返回（如 `{"error": "timeout"}`），让模型能自我修正。

## 5.2 MCP：模型上下文协议

MCP（Model Context Protocol）用"client-server"方式统一了工具接入协议：任何应用只要实现 MCP Server，即可被所有支持 MCP 的 Agent 复用，图 5-1 展示了这一星型拓扑。

![图5-1 MCP 协议：Host、Client 与 Server 的关系](figures/fig5_mcp.png)

MCP 提供三类原语：**Tools**（可执行动作）、**Resources**(可读取数据)、**Prompts**（可复用模板）。其价值在于把"N 个模型 × M 个工具"的适配成本从 N×M 降为 N+M。

## 5.3 代码解释器与安全沙箱

代码解释器是最强大的通用工具，也是最危险的工具，必须遵守：

1. 在容器/gVisor/Firecracker 等隔离环境中运行，默认**断网**。
2. 限制 CPU、内存、磁盘与执行时长配额。
3. 文件系统只挂载任务工作目录，禁止访问密钥与宿主路径。
4. 高危动作（转账、删除、发布）一律走人工确认（HITL）。

## 5.4 本章小结

工具层决定 Agent 能力边界，协议层（MCP）决定生态扩展速度。安全沙箱不是可选项——它是把"强大工具"变成"可交付产品"的前提。
