# 第3章 核心工作循环：ReAct

## 3.1 ReAct 范式

ReAct（Reasoning + Acting）是 Agent 最基础也最重要的工作循环，由三个步骤不断迭代构成：

1. **Thought（思考）**：分析当前状态与目标差距，决定下一步动作。
2. **Action（行动）**：从工具集中选择一个工具并给出参数。
3. **Observation（观察）**：读取工具返回结果，更新对世界的认知。

循环持续直到模型输出 `Final Answer` 或达到步数上限。图 3-1 展示了 ReAct 的闭环流程。

## 3.2 一个最小实现示例

```python
def react_loop(task, tools, max_steps=10):
    scratchpad = f"任务：{task}"
    for step in range(max_steps):
        thought, action = llm_plan(scratchpad)          # Thought
        if action is None:
            return thought                              # Final Answer
        observation = tools[action.name](**action.args) # Action
        scratchpad += f"\n思考：{thought}\n" \
                      f"行动：{action}\n观察：{observation}"
    return "达到最大步数，任务未完成"
```

要点说明：

- **Scratchpad（草稿纸）** 是把历史思考、行动、观察回灌给模型的关键，缺失它 Agent 会"失忆"。
- **停止条件**必须显式设置，防止无限循环消耗 Token。
- **解析失败兜底**：当模型输出不符合格式时，应重试或降级为直接回答。

## 3.3 常见变体

| 变体 | 改进点 | 适用场景 |
| --- | --- | --- |
| Plan-and-Execute | 先出完整计划再执行 | 长链条、结构清晰的任务 |
| Reflexion | 失败后自我反思再重试 | 代码生成、数学推理 |
| LATS | 树搜索 + 回溯 | 高价值、可回退的决策 |
| 并行工具调用 | 一次输出多个 Action | 检索、批量查询类任务 |

## 3.4 本章小结

ReAct 把"想"与"做"编织进同一个循环，是所有 Agent 框架的心跳。工程上真正决定成败的是循环之外的细节：轨迹管理、停止条件与异常兜底。
