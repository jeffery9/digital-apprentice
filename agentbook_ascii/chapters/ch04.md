# 第4章 记忆与知识管理

## 4.1 记忆的三种形态

Agent 的记忆体系可类比人类认知，分为三类：

- **工作记忆（Working Memory）**：即当前上下文窗口中的信息，容量有限、随会话结束消失。
- **情景记忆（Episodic Memory）**：历史交互轨迹的向量化存储，支持语义检索"上次我是怎么解决的"。
- **语义记忆（Semantic Memory）**：从经验中提炼的稳定知识与用户画像，通常写入结构化存储。

## 4.2 上下文工程（Context Engineering）

模型上下文窗口是 Agent 最稀缺的资源，常见治理手段：

1. **摘要压缩**：定期把早期轮次压缩为一段摘要，保留结论丢弃过程。
2. **滑动窗口 + 关键锚点**：始终保留系统提示、任务目标与最近 N 轮对话。
3. **外部化存储**：把长文档、中间产物写入文件/数据库，按需检索回灌。
4. **优先级裁剪**：Token 超限时按"目标 > 约束 > 事实 > 闲聊"的顺序淘汰。

## 4.3 RAG：检索增强生成

RAG 是情景/语义记忆最常用的落地形式，标准链路如下：

**离线**：文档 → 切块（Chunking）→ Embedding → 向量库。
**在线**：查询 → 向量召回 → 重排（Rerank）→ 拼接进 Prompt → 生成并标注引用。

实践要点：

- 切块大小以"语义完整"优先，代码按函数切、文档按标题切。
- 混合检索（BM25 + 向量）显著优于单一向量检索，尤其是专有名词场景。
- 必须做**引用溯源**，让每个论断都能回指到原始片段，抑制幻觉。

## 4.4 本章小结

记忆系统的本质是在"有限上下文"与"无限经验"之间做调度。好的记忆设计能让同一个模型在长任务中表现提升一个量级。
