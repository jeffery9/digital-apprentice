# 第2章 Agent 总体架构

## 2.1 分层架构模型

一个工业级 AI Agent 通常可以拆分为五层，自底向上依次为：

1. **模型层（Model Layer）**：基础大模型与推理引擎，决定智能上限。
2. **记忆层（Memory Layer）**：上下文窗口、向量库、结构化状态存储。
3. **规划层（Planning Layer）**：任务分解、反思（Reflection）、重规划。
4. **工具层（Tool Layer）**：函数调用、代码解释器、浏览器、MCP 服务。
5. **编排层（Orchestration Layer）**：循环控制、并行调度、人机协同（HITL）。

## 2.2 核心组件职责

| 组件 | 职责 | 常见实现 |
| --- | --- | --- |
| Planner | 目标拆解为子任务 DAG | ReAct、Plan-and-Solve、ToT |
| Executor | 执行单个子任务 | LLM 调用 + 工具运行沙箱 |
| Critic | 评估中间结果 | 规则校验、LLM-as-Judge |
| Memory | 存取知识与状态 | Redis、向量数据库、SQLite |
| Router | 模型/工具选择 | 成本-质量路由策略 |

## 2.3 设计原则

- **最小权限**：每个工具只授予完成任务所需的最小能力。
- **幂等重试**：所有副作用操作设计重试语义，避免重复扣款、重复发帖。
- **全程留痕**：每一步思考、调用、返回都写入轨迹（Trace），便于回放审计。
- **优雅降级**：模型超时或工具失败时，切换到备用链路而非直接崩溃。

## 2.4 本章小结

架构设计的核心是把"不确定的模型输出"约束在"确定的工程框架"内：上层用编排与校验兜底，下层用记忆与工具扩展能力边界。
